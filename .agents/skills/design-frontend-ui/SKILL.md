# 设计前端 UI

以“调查、实现、渲染、修正”的短反馈循环交付可用界面。视觉好看不是单独目标，必须同时证明信息易读、操作完整、项目一致且在目标视口真实可用。保持流程轻量，不为小改动生成额外设计文档。

## 1. 收集视觉事实

修改前检查：

- 目标页面、相邻页面和共用布局；
- 全局 CSS、主题变量、间距与圆角；
- 已有按钮、表单、弹窗、表格、导航和反馈组件；
- 项目已有图标库、字体、图片和品牌素材；
- 设计稿、截图、Figma 注释或用户指定参考。

此仓库管理端是 Next.js/React、Radix、Tailwind 和 Lucide；用户端是 Vue/Vite、Tailwind 和 Lucide。先确认改动属于哪个子项目，不跨栈复制组件。

设计资料的优先级为：用户明确要求 > 设计稿及注释 > 项目设计令牌与公共组件 > 相邻页面模式 > 新设计判断。Figma 生成代码只作参考，必须适配本项目。

## 2. 定义界面契约

在心里或工作记录中明确：

- 主要用户与最高频任务；
- 首屏最重要的信息和唯一主操作；
- 内容密度与阅读顺序；
- 必须支持的交互状态和目标视口；
- 不能改变的业务行为。

写一句内部设计主张，把用户、任务、密度和气质连起来，例如“面向高频运维的紧凑控制台：异常优先、中性底色、低干扰层级”。让布局、颜色、间距和动效服从同一判断，不把多套风格混在一起。不要把这句话显示在界面中。

需求仍有会显著改变用户行为的歧义时，交给 `$clarify-requirements`，不要用视觉猜测替代产品决定。

## 3. 先结构后装饰

1. 建立页面骨架、网格、尺寸约束和响应式断点。
2. 按真实工作顺序排定信息；运维和监控页面优先展示异常、风险与待处理对象，不让关键问题藏在正常项目之后。
3. 选用已有组件并补齐默认、悬停、聚焦、激活、禁用、加载、空、错误和成功状态。
4. 最后调整颜色、字体、边框、阴影和动效。

后台、CRM 和工作台保持紧凑、克制、便于扫描；不要套用营销页式英雄区、巨型标题或装饰性卡片墙。页面区段不伪装成悬浮卡片，也不在卡片中嵌套卡片。

统计数字、筛选数量、告警和列表应从同一数据源派生，不在多个位置重复硬编码业务口径。

## 4. 使用可靠的视觉规则

- 优先复用设计令牌；新增颜色必须有明确语义并兼容主题。
- 避免单一色系统治页面，避免紫蓝渐变、米色、蓝灰或棕橙成为无理由的默认审美。
- 卡片圆角默认不超过 8px，除非项目系统已有不同约束。
- 不添加渐变球、光斑、散景、无意义玻璃拟态和纯装饰 SVG。
- 字距保持 0，不使用负字距，不按视口宽度缩放字号。
- 控件保持稳定尺寸，长文本必须换行、截断或动态收缩，不能遮挡相邻内容。
- 真实产品和对象使用可检查的真实素材，不以占位图或模糊氛围图充数。

## 5. 让控件符合任务

- 工具操作使用 Lucide 图标；陌生图标提供 tooltip、`aria-label` 或屏幕阅读文本。
- 模式用分段控件，布尔值用开关或复选框，数值用输入、步进器或滑杆，视图用标签页，选项集合用菜单。
- 文字按钮只用于清晰命令。不要把常见图标动作做成带文字的圆角矩形。
- 带按钮、箭头、悬停或指针样式的元素必须真的可操作；暂未实现时去掉虚假的点击暗示。
- 键盘焦点清晰，颜色不是唯一状态信号，触控目标可点击。
- 界面文案服务业务，不在页面里解释设计特点、快捷键或使用方法。

## 6. 明确响应式策略

- 不把桌面布局简单等比缩小。分别决定侧栏、表格、工具栏、筛选器、弹窗和卡片在移动端如何折叠、重排或替换。
- 保留任务所需的关键上下文，例如状态、更新时间和主要操作；只隐藏真正次要的信息。
- 将状态并入标题或摘要行，避免移动卡片产生无意义的空行和纵向占用。
- 让长中文、英文、数字和最长单词换行或截断，不能遮挡相邻内容。
- 使用稳定尺寸避免布局跳动，并尊重 `prefers-reduced-motion`。

## 7. 做真实视觉检查

按 `$avoid-over-testing` 控制成本：

1. 运行能打开目标页面的最小开发环境。
2. 在代表性桌面视口检查层级、间距、资源、状态和交互。
3. 用户可见改动明显时，再检查一个移动端视口。
4. 查看截图与实际像素，确认页面非空、无重叠、无溢出、无错误裁切、素材正常加载。
5. 实际操作本次新增或修改的关键交互，例如搜索、筛选、弹窗或刷新；不要只检查控件存在。
6. 只修正观察到的高影响差异，最多进行三轮视觉修正；不要无限打磨。

若设计稿存在，按布局、内容、字体、颜色、间距、素材和交互状态逐项比较。构建成功、DOM 存在、源码正则或模拟 API 页面都不能替代真实视觉结果。

最终报告实现范围、实际检查结果、检查视口、尚未验证的真实数据状态和用户待验收事项。不要把“计划检查”写成已经验收。

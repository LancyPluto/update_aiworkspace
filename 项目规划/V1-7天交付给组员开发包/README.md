# AI 超市平台 V1 7 天交付开发包

本文档包用于 5 人小团队在 1 周内完成 V1 最小可交付版本。所有成员必须先阅读：

5. `08-推荐代码结构与模块边界.md`
6. `09-环境变量与本地启动清单.md`
7. `10-接口Mock与联调样例.md`
8. `15-从0开始脚手架搭建方案.md`
9. `16-一周从0开发排期修正版.md`
10. `17-DockerCompose本机一键启动方案.md`

## V1 目标

本周只交付一条核心闭环：

```text
管理员登录
→ 后台创建/配置 AI 工具
→ 配置动态字段和 Prompt
→ 发布工具
→ 用户登录
→ 用户看到工具
→ 用户提交任务
→ 后端创建任务并入队
→ Worker 调用 AI
→ 保存结果
→ 用户查看结果
→ 后台查看任务和失败原因
```

## 本周不做

```text
支付订单
套餐购买
算力审批流
复杂 RBAC 权限矩阵
完整监控告警系统
文件上传
素材库/RAG
图片/视频/数字人多模态
复杂 Prompt 回滚
多租户/企业空间
```

## 从 0 开始特别说明

本项目没有现成框架时，第 1 天必须优先完成脚手架和基础链路，不要直接分头写页面和接口。第 1 天验收标准是：

```text
后端能启动
用户端能启动
管理后台能启动
Worker 能启动
MySQL/Redis 能连接
前端能请求后端健康检查接口
```

如果第 1 天没有完成这个基础骨架，后续并行开发会非常容易失控。

## 本机演示建议

演示环境在本机时，建议用 Docker Compose 启动 MySQL 和 Redis，减少环境差异。后端、Worker、前端开发期可以先本地命令启动；第 7 天如时间允许，再把后端和 Worker 也接入 Compose。

## 每日合并节奏

```text
每天 17:00 前：各成员提交到个人分支
每天 18:00 前：1 号合并到 dev
每天 20:00 前：5 号完成核心链路回归
当天阻塞问题：当天修复，不带到最后一天
```

## 最终验收标准

只要下面 8 条全部通过，V1 即可交付：

```text
1. 用户能登录
2. 管理员能登录
3. 管理员能创建并发布一个工具
4. 用户能看到这个工具
5. 用户能提交任务
6. Worker 能完成 AI 生成
7. 用户能看到生成结果
8. 后台能看到任务状态和失败原因
```

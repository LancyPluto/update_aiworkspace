# 01. 成员 1：后端核心与架构

## 角色定位

你负责整个 V1 的后端主干、数据库一致性、接口总控、合并协调和部署。其他成员遇到接口/表结构争议时，以你维护的 `00-统一接口数据库契约.md` 为准。

## 本周目标

```text
让用户端、管理后台、Worker 都能围绕同一套后端 API 跑通主链路。
```

## 必须交付

1. 数据库初始化脚本。
2. 用户登录/注册/鉴权。
3. 管理员登录/鉴权。
4. 统一响应结构和错误码。
5. 任务创建、入队、状态查询、详情查询。
6. 算力账户冻结、扣除、释放。
7. Worker 内部回写接口。
8. 每日合并到 `dev` 分支并处理接口冲突。

## 任务创建事务

创建任务必须按此顺序：

```text
1. 校验用户登录
2. 校验工具存在且 ONLINE
3. 校验动态字段必填
4. 计算 params_hash
5. 做 10 秒内重复提交幂等检查
6. 查询 credit_accounts 并加锁
7. 校验 balance - frozen >= estimated_credit_cost
8. 冻结算力，写 credit_logs: FREEZE
9. 创建 ai_tasks，状态 CREATED
10. 保存 ai_task_inputs
11. 推入 Redis 队列
12. 更新任务状态 QUEUED
13. 写 ai_task_logs
14. 返回 taskId
```

如果 Redis 入队失败：

```text
任务标记 FAILED
释放冻结算力
写失败日志
返回 SYSTEM_ERROR 或明确失败信息
```

## Worker 成功回写事务

```text
1. 校验任务当前状态是 PROCESSING
2. 保存 ai_result_resources
3. 更新 ai_tasks 为 SUCCESS
4. frozen 减少，balance 减少
5. 写 credit_logs: DEDUCT
6. 写 ai_task_logs: TASK_SUCCESS
```

重复回写 SUCCESS 时：

```text
如果任务已经 SUCCESS，直接返回 SUCCESS，不重复扣费。
```

## Worker 失败回写事务

```text
1. 校验任务当前状态是 PROCESSING / RETRYING
2. 如可重试，更新 RETRYING 并重新入队
3. 如不可重试，更新 FAILED
4. 释放 frozen
5. 写 credit_logs: RELEASE
6. 写 ai_task_logs: TASK_FAILED
```

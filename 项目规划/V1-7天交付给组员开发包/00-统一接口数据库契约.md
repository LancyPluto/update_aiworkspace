# 00. 统一接口数据库契约

所有成员必须以本文为准。若本文和旧文档冲突，以本文为本周 V1 开发口径。

## 1. 统一技术边界

```text
前端用户端：Vue 或现有前端框架
管理后台：Vue 或现有后台框架
后端：Spring Boot REST API
数据库：MySQL
队列：Redis
AI 执行：Python Worker
AI 模型：先接 1 个文本生成模型
任务状态更新：V1 优先轮询，SSE 有余力再做
```

## 2. 统一响应结构

所有接口返回：

```json
{
  "code": "SUCCESS",
  "message": "ok",
  "data": {},
  "requestId": "optional-request-id"
}
```

失败返回：

```json
{
  "code": "PARAM_ERROR",
  "message": "参数错误",
  "data": null,
  "requestId": "optional-request-id"
}
```

## 3. V1 保留错误码


| 错误码                   | 含义              |
| --------------------- | --------------- |
| `SUCCESS`             | 成功              |
| `PARAM_ERROR`         | 参数错误            |
| `UNAUTHORIZED`        | 用户未登录或 Token 失效 |
| `FORBIDDEN`           | 无权限             |
| `ADMIN_UNAUTHORIZED`  | 管理员未登录          |
| `ADMIN_FORBIDDEN`     | 管理员无权限          |
| `TOOL_NOT_FOUND`      | 工具不存在           |
| `TOOL_OFFLINE`        | 工具未上线           |
| `CREDIT_NOT_ENOUGH`   | 算力不足            |
| `TASK_NOT_FOUND`      | 任务不存在           |
| `TASK_STATUS_INVALID` | 任务状态不允许操作       |
| `MODEL_CALL_FAILED`   | 模型调用失败          |
| `SYSTEM_ERROR`        | 系统异常            |


## 4. 统一任务状态

本周统一使用以下状态，不使用 `PENDING` / `RUNNING`：


| 状态           | 含义           | 是否终态 |
| ------------ | ------------ | ---- |
| `CREATED`    | 任务已创建        | 否    |
| `QUEUED`     | 已进入 Redis 队列 | 否    |
| `PROCESSING` | Worker 正在执行  | 否    |
| `RETRYING`   | 系统重试中        | 否    |
| `SUCCESS`    | 成功           | 是    |
| `FAILED`     | 失败           | 是    |
| `TIMEOUT`    | 超时           | 是    |
| `CANCELLED`  | 已取消          | 是    |


V1 状态流：

```text
CREATED → QUEUED → PROCESSING → SUCCESS
CREATED → QUEUED → PROCESSING → FAILED
CREATED → QUEUED → CANCELLED
PROCESSING → RETRYING → QUEUED
PROCESSING → TIMEOUT
```

## 10. Redis 队列消息

队列名：

```text
ai:task:queue
```

消息结构：

```json
{
  "taskId": 90001,
  "taskNo": "T202605070001",
  "toolCode": "xiaohongshu_copywriting",
  "traceId": "request-id",
  "createdAt": "2026-05-07T10:00:00"
}
```

Worker 不从队列消息读取完整 Prompt 和参数，必须通过后端内部接口或数据库查询任务详情，避免队列消息过大。

## 11. Worker 回写接口

内部接口由 1 号提供，3 号调用：


| 方法     | 路径                                                  | 说明            |
| ------ | --------------------------------------------------- | ------------- |
| `POST` | `/api/internal/v1/tasks/{taskId}/processing`        | Worker 开始执行   |
| `POST` | `/api/internal/v1/tasks/{taskId}/success`           | Worker 回写成功结果 |
| `POST` | `/api/internal/v1/tasks/{taskId}/failed`            | Worker 回写失败   |
| `GET`  | `/api/internal/v1/tasks/{taskId}/execution-context` | 获取任务执行上下文     |


成功回写请求：

```json
{
  "resourceType": "MARKDOWN",
  "contentText": "生成结果",
  "contentJson": null,
  "modelProviderCode": "deepseek",
  "modelName": "deepseek-chat"
}
```

失败回写请求：

```json
{
  "errorCode": "MODEL_CALL_FAILED",
  "errorMessage": "模型调用失败"
}
```

## 12. 算力简化规则

V1 本周采用固定算力：

```text
每个工具配置 estimated_credit_cost
创建任务时冻结算力
任务成功时 frozen 转 DEDUCT
任务失败/TIMEOUT 时 RELEASE
后台可手动加算力
不做套餐、有效期、支付、审批
```

# 06. 联调测试与合并规则

## 1. 分支规则

```text
main：稳定交付分支
dev：每日集成分支
feature/backend-core：1 号
feature/user-web：2 号
feature/worker-ai：3 号
feature/admin-web：4 号
feature/test-docs：5 号
```

## 2. 每日合并流程

```text
1. 每天 17:00 前，每个成员提交代码到自己的 feature 分支
2. 每天 17:00-18:00，1 号合并到 dev
3. 合并前必须能本地启动自己负责的模块
4. 合并后由 5 号跑核心链路测试
5. P0 问题当天必须修复
6. 第 7 天从 dev 合并 main
```

## 3. 接口变更规则

任何人不得私自改接口字段。必须按下面流程：

```text
1. 在群里说明要改什么接口/字段
2. 说明影响哪些成员
3. 1 号确认
4. 更新 00-统一接口数据库契约.md
5. 再改代码
```

## 4. 数据库变更规则

任何表名、字段名、状态枚举变更，都必须同步更新：

```text
00-统一接口数据库契约.md
数据库初始化脚本
后端实体/Mapper
接口返回字段
测试用例
```

禁止出现：

```text
前端用 taskStatus，后端返回 status
Worker 用 RUNNING，后端用 PROCESSING
后台用 ai_task_results，数据库是 ai_result_resources
```

## 5. 联调顺序

### 第一轮：登录和工具

```text
管理员登录
→ 创建工具
→ 配置字段
→ 配置 Prompt
→ 发布工具
→ 用户登录
→ 用户看到工具
```

### 第二轮：任务创建

```text
用户进入工具详情
→ 动态表单展示
→ 用户提交任务
→ 后端冻结算力
→ 任务进入 QUEUED
→ Redis 中存在任务消息
```

### 第三轮：Worker 执行

```text
Worker 消费任务
→ 任务变为 PROCESSING
→ 调用 AI
→ 回写 SUCCESS
→ 保存 ai_result_resources
→ 算力扣除
```

### 第四轮：查询和后台

```text
用户查询任务状态
→ 用户查看结果
→ 我的任务出现记录
→ 后台任务列表出现记录
→ 后台任务详情能看到输入、结果、失败原因、算力流水
```

## 6. P0 阻塞标准

以下问题必须立即修：

```text
无法登录
管理员无法发布工具
用户看不到已发布工具
任务无法创建
任务不入队
Worker 无法消费
结果无法保存
用户看不到结果
算力重复扣除
用户能看别人的任务
普通用户能访问后台
```

## 7. 最后一日冻结规则

第 7 天只允许：

```text
修 P0/P1 Bug
改文案
补测试数据
补部署文档
修演示阻塞问题
```

第 7 天禁止：

```text
新增大功能
改数据库大结构
改任务状态枚举
改核心接口路径
引入新技术栈
```

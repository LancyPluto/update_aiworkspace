# 13. 风险清单与决策记录

本文用于记录一周 V1 的范围决策和风险，避免开发中反复争论。

## 1. 已确认范围决策


| 决策        | 结果                                 | 原因                    |
| --------- | ---------------------------------- | --------------------- |
| 任务状态      | 使用 `CREATED/QUEUED/PROCESSING/...` | 和 V1 主文档、接口文档、数据库文档统一 |
| 结果表       | 使用 `ai_result_resources`           | 和数据库文档统一              |
| 实时状态      | 优先轮询                               | 一周内稳定性优先              |
| 算力        | 固定算力，冻结/扣除/释放                      | 保留核心商业闭环              |
| 权限        | 只区分 USER / ADMIN                   | 避免复杂 RBAC 拖慢开发        |
| 工具数量      | 先做 1-3 个                           | 先验证闭环                 |
| Prompt 回滚 | 不做复杂回滚                             | 可通过新建版本替代             |

## 3. 主要风险


| 风险              | 影响        | 应对                             |
| --------------- | --------- | ------------------------------ |
| Worker 和后端状态不一致 | 任务卡死或重复扣费 | Worker 只调用 internal 接口，由后端统一流转 |
| 前后端字段不一致        | 页面无法联调    | 所有人按 `10-接口Mock与联调样例.md` 开发    |
| 数据库字段临时变化       | 全员返工      | 字段变更必须先改统一契约                   |
| AI 模型不稳定        | 演示失败      | 准备 mock 模型开关或固定演示数据            |
| 最后一天新增功能        | 合并失败      | 第 7 天只修 Bug                    |
| 算力账务错误          | 影响核心可信度   | 5 号重点测试重复扣费和失败释放               |

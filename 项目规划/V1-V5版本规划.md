# 1. V1：企业级 MVP 版

## 1.1 版本定位

V1 是第一个真正可上线、可试运营的版本。

它不是简单 MVP，而是 **企业级 MVP**。意思是功能不追求多，但主链路必须稳定、可运营、可追踪。

## 1.2 核心目标

V1 要实现：

```
用户能找工具
用户能用工具
工具能通过后台配置
输入表单能动态生成
任务能异步执行
状态能实时展示
结果能保存
算力能扣除
后台能管理工具、Prompt、任务、用户、算力
```

原文档中已经提到第一阶段必须补齐 AI 工具超市列表页、分类体系、详情页、使用页、行业解决方案页、会员算力页、后台工具管理与 Prompt 管理等能力。但我建议 V1 要进一步收窄边界：重点做“工具超市 + 任务生成 + 后台配置 + 算力流水”，行业解决方案和学习中心可以先做轻量版。

## 1.3 V1 必做模块

| 模块         | 是否必做 | V1 范围                                      |

| 工作台       | 必做     | 推荐工具、最近任务、算力余额、快速入口       |
| AI 工具超市  | 必做     | 分类、搜索、工具卡片、热门工具               |
| 工具详情页   | 必做     | 工具说明、输入说明、输出说明、示例结果       |
| 工具使用页   | 必做     | 动态表单、创建任务、查看进度、展示结果       |
| 我的任务     | 必做     | 全部任务、生成中、已完成、失败任务、重新生成 |
| 会员与算力   | 必做     | 算力余额、消耗记录、套餐展示                 |
| 我的素材库   | 轻量做   | 只做收藏结果、企业基础资料                   |

| 行业解决方案 | 轻量做   | 固定行业推荐，不做智能推荐                   |

原文档中对工作台的定位是用户登录后的首页，需要展示需求搜索框、推荐工具、最近任务、算力余额等内容。这个设计可以保留，但 V1 不建议一开始做复杂自然语言需求分发，可以先用固定快捷入口。

## 1.4 V1 技术边界

### 必须实现

1. MySQL 保存用户、工具、任务、结果、算力流水
2. Redis 作为异步任务队列
3. Python Worker 执行 AI 任务
4. SSE 推送任务状态
5. 后端统一创建任务
6. 后台配置工具和 Prompt
7. 动态输入字段渲染
8. 基础限流
9. 任务失败重试
10. 操作日志

文档中已经建议前端读取 `ai_tools` 展示工具卡片，进入详情页后读取 `tool_input_fields` 渲染表单，用户提交后创建 `ai_task` 并推入 Redis 队列，Worker 读取 Prompt 生成结果，再通过 SSE 推送前端。V1 的技术实现应该严格围绕这条链路展开。

### 暂不实现

1. 多模型智能路由
2. 多 Agent 协作
3. 真正的视频生成
4. 数字人完整工作流
5. 企业微信/钉钉集成
6. 完整在线支付
7. 多租户组织架构
8. 开放 API 平台
9. 复杂 BI 数据分析
10. 大规模分布式部署

## 1.5 V1 推荐开发周期

假设 4 名研发实习生 + 1 名负责人，建议周期为 7 周。

| 周期    | 目标               | 主要任务                                         |
| ------- | ------------------ | ------------------------------------------------ |
| 第 1 周 | 需求冻结与技术设计 | 确定 V1 范围、表结构、接口、任务状态机           |
| 第 2 周 | 后台工具配置       | 工具分类、工具管理、Prompt 管理、字段配置        |
| 第 3 周 | 用户端工具超市     | 工作台、工具列表、详情页、动态表单               |
| 第 4 周 | 任务链路           | 任务创建、Redis 队列、Worker、模型调用、结果保存 |
| 第 5 周 | 任务中心与算力     | 我的任务、失败重试、算力账户、算力流水           |
| 第 6 周 | 安全与可靠性       | 鉴权、限流、幂等、日志、SSE 兜底、异常处理       |
| 第 7 周 | 联调验收上线       | 功能测试、异常测试、部署、灰度试运行             |

## 1.6 V1 验收标准

V1 不能用“页面做完了”作为验收标准，而要用业务闭环验收。

### 用户侧验收

1. 用户可以注册登录
2. 用户可以进入工作台
3. 用户可以浏览 AI 工具超市
4. 用户可以按分类筛选工具
5. 用户可以进入工具详情页
6. 用户可以填写动态表单
7. 用户可以创建 AI 任务
8. 用户可以看到任务进度
9. 用户可以看到生成结果
10. 用户可以复制、收藏、重新生成结果
11. 用户可以查看历史任务
12. 用户可以查看算力余额和消耗记录

### 管理侧验收

1. 管理员可以新增工具
2. 管理员可以上下架工具
3. 管理员可以配置工具输入字段
4. 管理员可以配置 Prompt
5. 管理员可以查看所有任务
6. 管理员可以查看失败原因
7. 管理员可以给用户加减算力
8. 管理员可以查看 API 消耗日志

### 技术侧验收

1. 任务重复提交不会重复扣费
2. Worker 失败后任务状态可追踪
3. SSE 断开后轮询能恢复状态
4. Prompt 修改后新任务生效，旧任务可追踪版本
5. 算力流水和任务记录一致
6. 模型调用失败有明确错误信息
7. 后台操作有审计记录

# 2. V2：商业化增强版

## 2.1 版本定位

V2 的目标是从“可试运营”升级为“可收费运营”。

V1 可以手动给用户加算力，但 V2 要形成完整商业闭环。

## 2.2 核心目标

```
套餐可配置
订单可创建
支付可接入
发票/合同可扩展
运营数据可分析
用户增长可追踪
```

## 2.3 必做内容

### 2.3.1 会员套餐系统

| 功能       | 说明                           |
| ---------- | ------------------------------ |
| 套餐配置   | 免费版、基础版、专业版、企业版 |
| 套餐权益   | 每月算力、可用工具、并发任务数 |
| 套餐有效期 | 月付、季付、年付               |
| 套餐升级   | 用户可从低套餐升级到高套餐     |
| 套餐过期   | 到期后降级或限制使用           |

### 2.3.2 订单与支付

| 功能     | 说明                           |
| -------- | ------------------------------ |
| 订单创建 | 用户购买套餐时创建订单         |
| 支付接入 | 微信支付、支付宝或手动转账     |
| 支付回调 | 回调验签、幂等处理             |
| 订单状态 | 待支付、已支付、已取消、已退款 |
| 充值记录 | 记录用户充值和套餐购买         |

原文档中把订单管理放在第二阶段，是合理的。V1 先做算力流水，V2 再接支付，可以避免第一版复杂度过高。

### 2.3.3 运营后台增强

| 模块     | 功能                             |
| -------- | -------------------------------- |
| 数据看板 | DAU、WAU、任务数、收入、API 成本 |
| 工具分析 | 热门工具、转化率、失败率         |
| 用户分析 | 新增用户、活跃用户、付费用户     |
| 收入分析 | 套餐收入、充值收入、退款         |
| 成本分析 | 模型 API 消耗、单任务成本        |

## 2.4 V2 不做内容

1. 多租户企业组织
2. 开放 API
3. 大规模插件市场
4. 复杂 RAG 知识库
5. 数字人完整生成链路

## 2.5 V2 验收标准

1. 用户可以购买套餐
2. 支付成功后自动增加权益
3. 支付回调不会重复开通
4. 管理员可以查看订单
5. 管理员可以配置套餐
6. 用户可以查看购买记录
7. 后台可以统计收入和 API 成本
8. 平台可以初步计算毛利

------

# 3. V3：智能推荐与素材库版

## 3.1 版本定位

V3 的目标是从“工具超市”升级为“懂行业、懂客户、可复用资料的 AI 经营助手”。

V1 解决“用户能用工具”，V2 解决“平台能收费”，V3 解决“生成质量和复用效率”。

## 3.2 核心目标

```
用户不只是选择工具
而是输入行业和目标
系统推荐合适工具组合
并自动引用企业资料、产品资料和历史内容
```

## 3.3 必做内容

### 3.3.1 素材库增强

当前文档已经提到素材库用于保存企业资料、产品资料、素材和常用生成结果，并为后续精准生成打基础。V3 应该正式把它升级为“企业资料中心”。

| 模块     | 功能                               |
| -------- | ---------------------------------- |
| 企业资料 | 企业介绍、品牌定位、行业、目标客户 |
| 产品资料 | 产品名称、卖点、价格、适用人群     |
| 客户资料 | 用户画像、客户标签、常见问题       |
| 内容资产 | 历史文案、脚本、活动方案           |
| 文件上传 | 支持 PDF、Word、Excel、图片        |
| 资料引用 | 生成任务时自动引用企业资料         |

### 3.3.2 RAG 知识库

| 功能     | 说明                     |
| -------- | ------------------------ |
| 文件解析 | 解析企业资料、产品文档   |
| 文本切片 | 按段落、标题、语义切分   |
| 向量化   | 建立向量索引             |
| 召回     | 根据用户任务召回相关资料 |
| 生成融合 | 把召回内容注入 Prompt    |
| 引用溯源 | 显示结果依据哪些资料生成 |

### 3.3.3 行业推荐

| 功能         | 说明                                         |
| ------------ | -------------------------------------------- |
| 行业选择     | 餐饮、美业、教育、电商、本地生活             |
| 目标选择     | 获客、转化、复购、活动、直播                 |
| 推荐工具组合 | 根据行业和目标推荐工具                       |
| 推荐任务流   | 例如“一周短视频计划 + 朋友圈文案 + 活动方案” |
| 固定规则优先 | 先用规则，不急着上复杂算法                   |

## 3.4 V3 不做内容

1. 开放插件市场
2. 企业多组织复杂权限
3. 全自动 Agent 工作流
4. 全自动视频剪辑
5. 大规模模型训练

## 3.5 V3 验收标准

1. 用户可以维护企业资料
2. 用户可以维护产品资料
3. 工具生成时可以引用资料
4. 用户可以看到资料引用来源
5. 行业方案可以推荐工具组合
6. 生成结果相比 V1 更贴合用户业务
7. 后台可以管理行业推荐规则

# 5. V5：企业级 SaaS 最终版

它不再只是一个 AI 工具网站，而是一个可面向企业客户交付的 SaaS 平台。

## 5.2 核心目标

```
支持企业组织
支持团队协作
支持多角色权限
支持企业知识库
支持工作流
支持开放 API
支持私有化部署
支持规模化运维
```

## 5.4 V5 验收标准

1. 一个企业可以创建独立空间
2. 企业成员之间权限隔离
3. 企业资料库可共享
4. 团队可协作完成内容生成
5. 工作流可串联多个工具
6. 外部系统可通过 API 调用平台能力
7. 平台可支持私有化部署
8. 系统具备监控、备份、审计和灰度能力

# 商业上线 P0 发布门禁（2026-06-30）

本门禁用于商业上线前最后检查。目标是先封住安全、计费、队列和生产路径风险，再继续做运营增长功能。

## 1. 密钥与生产启动

- 真实 `.env`、`WXcert/*.pem`、`_remote.py`、`_fix_remote.py` 不允许进入 Git；仓库只保留 `.env.example`。
- 上线前必须轮换所有曾经入库或可能泄露的支付证书、内部 token、部署密码和模型 API Key。
- `APP_PRODUCTION_MODE=true` 或 `APP_ENV=production` 都视为生产环境。
- 生产环境必须拒绝：
  - `INTERNAL_API_TOKEN=local-internal-token` 或 `replace-with-internal-token`
  - `MODEL_API_KEY=replace-with-model-key` 或空值
  - `MODEL_PROVIDER=mock`
  - 后端通配 CORS

## 2. 队列与任务结算

- 生产任务队列事实源为 RabbitMQ：`TASK_QUEUE_BACKEND=rabbitmq`。
- Redis 队列只允许本地开发或历史兼容；生产环境配置 Redis 队列必须启动失败。
- Worker 启动日志必须能看到队列后端、队列名、死信队列、重试延迟和最大重试次数。
- 管理端可调用 `POST /api/admin/v1/tasks/reconcile-stale` 对长时间卡在 `QUEUED/PROCESSING` 的任务做超时对账并释放冻结算力。

## 3. Mock 与 Legacy

- 用户端和管理端 mock 数据只能通过显式开发开关启用，生产构建不允许生效。
- mock 支付不得作为生产路径；当前后端 mock payment 会返回不可用。
- 旧 `/api/v1/ai-tools` 与 `/api/admin/ai-tools` 仅作为兼容路径保留，并记录废弃日志；新代码必须使用 `/api/v1/tools` 与 `/api/admin/v1/tools`。
- PPT 工作流保存统一写入 `tool-integration` 配置；旧 `ppt-workflow` marker 仅保留读取兼容。

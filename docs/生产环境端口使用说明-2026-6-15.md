> 服务器：`8.134.93.203`（阿里云 ECS）  
> 域名：`wlcloudai.com` / `www.wlcloudai.com`（当前主要使用 **HTTP**）  
> 部署目录：`/root/ai_tool_market`

本文描述 **2026-06-15** 时在产线实测的端口绑定与访问路径，供运维、排查防火墙/CD 问题时查阅。

## 1. 总览架构

```text
Internet / 用户浏览器
        │
        ▼  :80 / :443（公网开放）
┌───────────────────┐
│  nginx 容器        │  ai-supermarket-nginx
│  反代 + 静态资源    │
└─────────┬─────────┘
          │ Docker 内网（服务名互访，无 host 端口）
    ┌─────┼─────┬──────────┬────────────┐
    ▼     ▼     ▼          ▼            ▼
 user-web  admin-frontend  backend  agent-service  worker
    │                        │            │
    │                        ├─ mysql:3306（容器内）
    │                        ├─ redis:6379
    │                        └─ rabbitmq:5672
    │
    └─ 用户端静态文件由 nginx 从 volume 提供

宿主机 mihomo（出站代理，非业务入口）
    :7890 混合代理（容器经 host.docker.internal:7890 出站）
    :9090  控制 API（仅 127.0.0.1）
```

**设计原则**

| 类型 | 绑定方式 | 说明 |
|------|----------|------|
| 对用户公开 | `0.0.0.0:80/443` | 仅 nginx |
| 运维/debug | `127.0.0.1:<port>` | 需 SSH 到服务器后本机访问 |
| 容器互访 | Docker network 服务名 | 如 `http://backend:8080` |
| 出站代理 | mihomo `7890` | backend/worker/agent-service 访问外网模型 API |

## 2. 公网入口（用户可访问）

| 端口 | 协议 | 进程/容器 | 用途 | 访问示例 |
|------|------|-----------|------|----------|
| **80** | HTTP | `ai-supermarket-nginx` | 主站入口（当前生产主要使用） | http://wlcloudai.com/ |
| **443** | HTTPS | `ai-supermarket-nginx` | TLS 入口（证书已配置，可按需启用） | https://wlcloudai.com/ |

### nginx 路由（`deploy/nginx/snippets/app_locations.conf`）

| 路径 | 反代目标 | 说明 |
|------|----------|------|
| `/` | 静态 `user_web_dist` volume | 用户端 SPA（Vue 构建产物） |
| `/assets/*` | 同上 | 带 hash 的静态资源，长缓存 |
| `/build-info.json` | 同上 | 部署指纹（git sha / 构建时间） |
| `/admin` | `admin-frontend:5174` | 管理后台（Next.js，`basePath=/admin`） |
| `/api/*` | `backend:8080` | 用户端 & 管理端 REST API |
| `/generated/*` | `backend:8080` | 本地遗留媒体（逐步迁移 OSS） |
| `/api/internal/*` | **404** | 禁止外网访问内部 API |
| `/healthz` | nginx 自身 | 健康检查，返回 `ok` |

**域名行为（`deploy/nginx/default.conf`）**

- `www.wlcloudai.com` → 301 跳转 `http://wlcloudai.com`
- `8.134.93.203` 也可作为 `default_server` 访问同一套路由

## 4. 宿主机代理（mihomo）

| 端口 | 绑定 | 用途 |
|------|------|------|
| **7890** | `0.0.0.0`（全接口） | HTTP/HTTPS/SOCKS 混合代理；**生产容器出站统一使用此端口** |
| **9090** | `127.0.0.1` | mihomo REST API / 控制面板 |

### 容器如何走代理

`deploy/docker-compose.yml` 为 `backend`、`worker`、`agent-service` 注入：

```env
HTTP_PROXY=http://host.docker.internal:7890
HTTPS_PROXY=http://host.docker.internal:7890
NO_PROXY=localhost,127.0.0.1,mysql,redis,...,wlcloudai.com,8.134.93.203,.aliyuncs.com,...
```

CD 流水线（`deploy/scripts/ci_remote_deploy_light.sh`）在每次部署时将 **根目录 `.env` 与 `deploy/.env` 均 patch 为 7890**，确保容器出站代理端口与 mihomo 一致。

**常见故障**：容器内 `Connection error` 访问 DeepSeek 等外网 API → 检查 mihomo 是否运行、容器 `HTTP_PROXY` 是否为 `7890`。

## 6. 防火墙 / 安全组建议

**应对外网开放**

- TCP **80**（HTTP）
- TCP **443**（HTTPS，若启用）

**建议不对公网开放**（仅 127.0.0.1 或内网）

- 8080、8090、5173、5174、3307、6379、5672、15672、7890、9090、1455、5001

阿里云安全组若误开 8080/3307 等，应收紧至 SSH 跳板或 VPN。

## 7. 常用排查命令（SSH 登录后）

```bash
# 查看所有容器端口
docker ps --format 'table {{.Names}}\t{{.Ports}}'

# 查看宿主机监听
ss -tlnp | grep -E '80|443|7890|8080|8090'

# 检查容器代理环境变量
docker exec ai-supermarket-agent-service printenv HTTP_PROXY HTTPS_PROXY

# 从容器测试 DeepSeek 连通（应返回 401 而非 Connection refused）
docker exec ai-supermarket-agent-service python -c \
  "import httpx; print(httpx.get('https://api.deepseek.com', timeout=10).status_code)"

# nginx 健康
curl -s http://127.0.0.1/healthz
```

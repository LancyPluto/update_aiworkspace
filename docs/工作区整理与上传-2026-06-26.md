# 工作区整理与上传记录 - 2026-06-26

## 本轮目标

本轮围绕 Agent 对话编辑后的多分支持久化、分支上下文隔离和图片工具记忆串线问题做收口。核心目标是让 `/agent` 页面达到长期可用的树状分支模型：前端只展示并继续当前 active path，后端以 `agent_messages.parent_message_id` 作为唯一事实来源，工具结果和 `<SessionState>` 也必须跟随当前分支。

## 关键改动

### 树状消息模型

- `agent_messages` 增加 `parent_message_id`，通过自关联表达对话树。
- `agent_sessions` 增加 `active_leaf_message_id`，记录当前会话默认展示和继续发送的叶子节点。
- 旧线性会话迁移为一条 parent 链，历史 `ACTIVE` 消息按 `id ASC` 回填父子关系。
- `status='ACTIVE'` 不再表示唯一线性路径；旧分支仍然是可用节点，只是不在当前 active path 上。

### 编辑、重生成与分支切换

- 编辑用户消息时不再覆盖原消息，也不再 `SUPERSEDED` 后续消息，而是创建一个新的 USER sibling。
- 普通发送会把新 USER 消息挂到当前 `active_leaf_message_id` 下。
- AI 回复挂到对应 USER 消息下，完成后更新会话 active leaf。
- 新增分支切换接口：
  - `POST /api/v1/agent/sessions/{sessionId}/branches/active`
  - 请求体包含 `anchorMessageId` 和 `variantMessageId`
  - 后端解析所选 variant 子树的最新 leaf，更新 active leaf，并返回新的 active path。

### 前端对话页

- `/agent` 消息列表改为以服务端 active path 为准，不再依赖本地 `branchHistory` 作为长期事实来源。
- 发送消息时传当前 active path 末尾消息 id 作为 `parentMessageId`。
- 被编辑过的 USER 消息和可重生成的 ASSISTANT 消息都会展示分支切换器。
- 点击分支切换器后调用后端 active branch 接口，刷新为服务端返回的分支路径。

### 分支上下文隔离

- `/context` 构造 history 时改为通过当前 source user message 的祖先路径获取上下文。
- `AgentContextSnapshot` 不再保存完整分支历史 JSON，仅保存 `leafMessageId`、`ancestorMessageIds`、预览和统计信息。
- `recentToolCalls` 和“近期工具结果摘要”改为按当前分支祖先 runIds 查询。
- 修复图片编辑串线：兄弟分支里的七海千秋、时崎狂三、四系乃等工具调用结果不会再互相污染 `<SessionState>.latest_generated_image`。

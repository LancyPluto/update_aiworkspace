# CDN / OSS 引入规划（2026-06-11）

## 一、现状梳理

当前所有媒体资产都落在**单机本地磁盘**，没有任何对象存储或 CDN：

| 环节 | 现状 |
|------|------|
| 存储根目录 | `data/generated-media`（Docker 内 `/data/generated-media`，backend 与 worker 共享 bind mount） |
| 用户上传 | 头像 `avatars/`、上传 `uploads/{日期}/`、工具封面 `tool-covers/`、市场附件 `market-files/` 等 |
| AI 生成产物 | worker 下载第三方临时 URL 后写盘：`images/{taskId}/`、`video/{taskId}/`、`audio/{taskId}/` |
| URL 形式 | 统一相对路径 `/generated/...`，由 worker `GENERATED_MEDIA_PUBLIC_BASE_URL=/generated` 拼接 |
| 访问链路 | 浏览器 → nginx `/generated/` 反代 → backend Spring ResourceHandler 读磁盘 |
| 前端静态资源 | user-web 构建产物在 `user_web_dist` volume，nginx 直出 `/assets/`（已带 immutable 缓存头）；admin 全程反代 Next.js |
| 已有云依赖 | 仅阿里云 Captcha/SMS SDK，无 OSS/S3 SDK |

### 主要风险与瓶颈
1. **单点**：媒体文件只存在阿里云单台 ECS 磁盘上，磁盘损坏/重装即全部丢失，无副本。
2. **带宽/性能**：视频文件经 nginx→backend（Java 静态资源处理）两跳转发，吞吐受 ECS 带宽和 JVM 限制，高并发播放会先打满出口带宽。
3. **磁盘膨胀**：AI 视频/音频持续累积，单盘容量上限可预见地会成为运维负担。
4. **扩容受阻**：未来 backend/worker 想多副本横向扩展，必须共享存储，本地盘方案天然不支持。

## 二、目标方案：阿里云 OSS + CDN

选型理由：服务器已在阿里云（8.134.93.203），同区域 OSS 内网上传免流量费、延迟最低；CDN 与 OSS 原生集成；后续 HTTPS 证书也可托管在 CDN 上。

### 目标架构

```
worker 生成媒体 ──(内网 endpoint 上传)──→ OSS Bucket（私有读 or 公共读）
backend 用户上传 ──(内网 endpoint 上传)──→ OSS Bucket
浏览器 ←── CDN（media.wlcloudai.com，回源 OSS） ←── OSS
旧文件：保留 /generated/ 本地兜底，逐步迁移
```

### Bucket 与目录规划

| Bucket | 用途 | 读权限 |
|--------|------|--------|
| `wlcloud-media`（标准存储） | AI 生成图片/视频/音频、用户上传、头像、封面 | 公共读（或私有+CDN 鉴权） |
| `wlcloud-archive`（低频/归档，可选二期） | 超过 N 天的历史任务产物 | 私有 |

目录沿用现有相对路径约定（`images/{taskId}/`、`avatars/{userId}/` 等），保证 URL 迁移只换前缀。

## 三、代码改造点（按链路）

### 1. 存储抽象层（backend，~1 天）
新增 `MediaStorageService` 接口 + 两个实现：
- `LocalMediaStorage`（现状，默认）
- `OssMediaStorage`（`aliyun-sdk-oss`，使用内网 endpoint）

配置开关（application.yml / 环境变量）：

```yaml
app:
  media-storage:
    mode: ${MEDIA_STORAGE_MODE:local}   # local | oss
    public-base-url: ${MEDIA_PUBLIC_BASE_URL:/generated}  # oss 模式填 https://media.wlcloudai.com
    oss:
      endpoint: ${OSS_ENDPOINT:}        # 内网 endpoint
      bucket: ${OSS_BUCKET:}
      access-key-id: ${OSS_AK:}
      access-key-secret: ${OSS_SK:}
```

改造调用方：`UserProfileServiceImpl`（头像）、`UserUploadController`、`AiMarketFileServiceImpl`、工具封面上传、客服二维码上传——全部改为走 `MediaStorageService.save(relativePath, bytes) -> publicUrl`。

### 2. worker persister（~0.5 天）
`generated_image_persister.py` / `generated_video_persister.py` / `generated_audio_persister.py` 增加 OSS 分支（`oss2` SDK）：
- `MEDIA_STORAGE_MODE=oss` 时直接 `put_object` 到 OSS，返回 `{MEDIA_PUBLIC_BASE_URL}/{relative_path}`；
- 保留本地模式作为回退；上传失败时降级写本地盘并打 WARN。

### 3. URL 兼容（关键，~0.5 天）
- 数据库里已有大量 `/generated/...` 相对 URL（任务产物、社区帖子、头像），**不批量改库**。
- nginx `/generated/` 维持反代 backend，旧 URL 永久可用。
- 新产物统一产出完整 CDN URL；前端已有逻辑同时兼容相对/绝对 URL（`resolveAssetUrl` 类工具函数处确认一遍即可）。

### 4. nginx / CDN（运维，~0.5 天）
- CDN 域名 `media.wlcloudai.com` → 回源 OSS bucket；缓存策略：图片 30 天、音视频 30 天、`Cache-Control: public, max-age=2592000`。
- 主站 `/assets/`（user-web 构建产物）二期可同样上 CDN（构建后上传 OSS + HTML 引用 CDN 前缀），一期不动。
- 注意当前只有 HTTP：CDN 可同时开 HTTP/HTTPS，等主站切 HTTPS 后再强制跳转。

### 5. 迁移与运维脚本（~0.5 天）
- `deploy/scripts/migrate_media_to_oss.py`：遍历 `data/generated-media` 全量 `ossutil cp` 上传（保留相对路径），可重复执行（按 ETag/size 跳过）。
- 迁移完成后本地盘转为冷备，每周快照。

## 四、实施节奏建议

| 阶段 | 内容 | 验收标准 |
|------|------|----------|
| 一期（1~2 天） | OSS bucket + CDN 域名开通；backend/worker 存储抽象 + 双模式开关；新产物写 OSS | 新生成的图片/视频 URL 为 `media.wlcloudai.com`，旧 `/generated/` URL 不受影响 |
| 二期（0.5 天） | 全量迁移历史文件到 OSS；`/generated/` 反代改为 301 到 CDN（或保留反代） | 历史社区帖子媒体可正常访问 |
| 三期（可选） | user-web `/assets/` 静态资源上 CDN；HTTPS 全站化；低频归档策略 | 首屏静态资源命中 CDN |

## 五、成本与注意事项

- **成本量级**：OSS 标准存储约 0.12 元/GB/月；CDN 流量约 0.24 元/GB（按量）。当前体量预计每月几十元内。
- **安全**：AK/SK 用 RAM 子账号（仅该 bucket 读写权限），通过环境变量注入 docker compose，**不进 git**。
- **防盗链**：CDN 上配置 Referer 白名单（wlcloudai.com）+ 可选 URL 鉴权（一期可不开）。
- **回滚**：`MEDIA_STORAGE_MODE=local` 一键回退，新旧 URL 互不影响。
- **PPT 引擎**（banana-slides 的 `/app/uploads`）独立存储，一期不动，二期并入统一抽象。

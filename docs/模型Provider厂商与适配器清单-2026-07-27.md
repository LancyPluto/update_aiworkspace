# 模型 Provider 厂商与适配器清单（2026-07-27）

> **阅读口径：** 第 1～8 节记录截至 2026-07-27 的源码与生产库只读快照。快照中的 `openai_gateway` 是当日客观存在的数据，不代表后续认可其为领域上的真实厂商。第 9 节单独记录此后确认的目标领域模型；两种口径不得混写。

## 1. 结论

- Provider 注册中心的首版核心设计者是 Git 记录中的 **Diend**。提交 `a2c0556625ab4206e8d0f031b32de26843e3a1ed` 于 2026-05-17 同时引入后端 YAML 注册表、`ModelProviderRegistry`、能力校验和 Worker Provider Registry。
- 现在的实现已经不是 Diend 一个人设计的版本，而是多人持续演进的结果。厂商账户、元数据字段、多能力、连通性探活、具体 Provider 和运行时客户端分别由不同作者补充。
- 当前源码 YAML 定义 **27 个 Provider**，按现有厂商目录归为 **13 个厂商/内部类别**（其中 `mock` 是内部类别，不是外部厂商）。2026-07-27 的生产库只读快照同样查询到 13 个厂商目录项、27 个 Provider 元数据项。
- Java 的 `ModelProviderAdapter` 目前只有接口，仓库中没有实现类，也没有消费方。真正发起模型请求的适配代码主要位于 Agent Service 和 Worker 的 Python client/handler 中。
- `adapterInstalled=true`、`adapterKey` 或 `workerReady=true` 只能视为元数据声明，不能单独证明真实执行链路已经接通。

本文只记录代码、元数据和只读生产快照，不包含 API Key、密码等凭据，也没有调用付费模型验证生产可用性。

## 3. 快照中的术语与真实运行关系

| 层级 | 本项目中的含义 | 主要代码 |
| --- | --- | --- |
| Vendor | 厂商目录和账户归属，例如 `minimax`、`qwen`、`volcengine` | [`VendorCodeResolver.java`](../backend/src/main/java/com/aiminilab/aitoolmarket/agent/support/VendorCodeResolver.java)、`model_vendors` |
| Provider | 可配置的服务入口，声明能力、默认模型、协议和就绪状态，例如 `minimax_speech` | [`model-providers.yml`](../backend/src/main/resources/model-providers.yml)、`model_provider_metadata` |
| Protocol | 可复用的上游接口契约，例如 `openai_chat`、`openai_images`、`vidu_async` | YAML/数据库元数据及 Worker Registry |
| Runtime Adapter | 实际构造请求、鉴权、轮询和解析响应的 client/handler | [`agent-service/app/clients`](../agent-service/app/clients)、[`worker/client`](../worker/client)、[`worker/handlers`](../worker/handlers) |

当前存在三套需要同步维护的映射：

1. 后端 [`model-providers.yml`](../backend/src/main/resources/model-providers.yml) 定义源码清单；`ModelProviderRegistry` 启动时加载它。
2. 数据库 `model_provider_metadata` 是管理 API 的优先数据源；只有数据库无可用数据或查不到指定 Provider 时，才回退 YAML。`DataInitializer` 只插入缺失项，不更新已有行。
3. Worker 的 [`providers/registry.py`](../worker/providers/registry.py) 是手工维护的子集；媒体 handler 按这里的能力和 `provider_protocol` 分派。Agent 文本链路另由 [`chat_model_factory.py`](../agent-service/app/clients/chat_model_factory.py) 维护别名和客户端选择。

任务执行快照目前不携带 `providerProtocol` 或 `adapterKey`，所以 Worker 不能完全依赖后端元数据动态选择适配器。这也是 YAML、数据库与 Worker Registry 容易漂移的根因。

## 6. 按能力看共享适配器

| 能力 | 执行入口 | 共享适配关系 |
| --- | --- | --- |
| 文本/Agent | `ChatModelFactory`、Agent/Worker `ModelClient` | OpenAI、DeepSeek、Qwen、Agnes 和通常的 MiniMax 共用 OpenAI Chat 兼容链路；Anthropic 兼容链路单独处理；MiniMax 旧协议按 URL 分支 |
| 图片 | `ImageGenerationHandler` | SiliconFlow 使用 `SiliconFlowVideoClient`；可灵使用 `KlingVideoClient`；火山、oFox、通用 OpenAI 网关和 Agnes 共用 `OpenAIImagesClient` |
| 视频 | `VideoGenerationHandler`、`DigitalHumanVideoHandler` | 可灵、Seedance、Agnes、百炼 HappyHorse 各有客户端；InfiniteTalk 仅在数字人链路使用 |
| TTS | `TextToSpeechClient` | 一个客户端内维护 MiniMax、SiliconFlow、DashScope Qwen 三个协议分支 |
| 音乐 | `MusicGenerationHandler` | 当前只有 `suno_music` 接到 `SunoMusicClient` |
| 主体同步 | Worker subject registry | 当前只有 `kling_video` 接到 `KlingSubjectAdapter` |

漫剧 `WorkflowStepHandler` 还有一层工作流专用兼容逻辑：图片的 `openai_images` 协议走 `OpenAIImagesClient`，其他图片协议默认走 SiliconFlow；视频仅 `agnes_video` 单独走 Agnes，其他默认走 Seedance。它不是通用 Provider 分派器，不应据此认定所有 Provider 都支持漫剧节点。

## 7. 辅助 Adapter 不等于模型执行 Adapter

### 7.1 余额适配器

[`VendorBalanceAdapterRegistry`](../backend/src/main/java/com/aiminilab/aitoolmarket/agent/balance/VendorBalanceAdapterRegistry.java) 管理的是厂商账户余额查询。目前有 DeepSeek、SiliconFlow、MiniMax、火山引擎、可灵、OpenAI/OpenAI 网关和 Suno 的实现。它们只负责余额接口，不生成文本、图片、视频或音频。

### 7.2 连通性探活

[`ConnectivityProbeRegistry`](../backend/src/main/java/com/aiminilab/aitoolmarket/agent/connectivity/ConnectivityProbeRegistry.java) 管理账户/模型探活策略。目前主代码中只有 `ModelsAccountConnectivityProbe implements ProviderConnectivityProbe`，并且 `ModelsEndpointResolver` 只支持 Agnes 账户的 `/models` 探活。该 Registry 证明的是地址和凭据的可达性，不是生产模型执行适配器。

## 8. 生产快照与源码偏差

2026-07-27 的生产数据库只读盘点结果：

- `model_vendors` 查询到 13 个当前厂商目录项：`kling`、`volcengine`、`siliconflow`、`deepseek`、`qwen`、`minimax`、`suno`、`openai`、`vidu`、`openai_gateway`、`agnes`、`infinitetalk`、`mock`。
- `model_provider_metadata` 查询到 27 个 Provider 元数据项，与本文件第 5 节的 Provider code 集合一致。
- 生产库将 `siliconflow_asr.worker_ready` 标为真，但源码 YAML 和 Worker Registry 均为假，且仓库中没有 ASR 执行客户端。这是明确的数据漂移，应以“未就绪”处理。
- `local_media_mock`、`worker_video` 在 YAML/Worker Registry 中标记就绪，但实际 handler 没有执行分支。
- Worker Registry 有 24 个 code：比 YAML 少 `deepseek`、`qwen`、`vidu_video`、`vidu_audio`，同时多一个仅用于兼容旧配置的 `siliconflow`。`deepseek`、`qwen` 仍可通过不查 Worker Registry 的通用文本路径执行；Vidu 两项不可执行。
- `VendorCodeResolver` 只映射了协议名 `vidu_async -> vidu`，没有映射实际 Provider code `vidu_video`、`vidu_audio`，URL 推断也不识别 `vidu.com`。当前这两项可能被误归为各自 Provider code。`local_media_mock` 同样没有显式归到 `mock`。
- `worker/client/skywork_video_client.py` 存在，但没有被 handler 导入或调用，也没有对应的 YAML Provider；它是孤立客户端，不计入 27 个 Provider 的已接线适配器。

数据库优先读取加上“只插入、不更新”的初始化策略意味着：修改 YAML 不会自动修正生产已有元数据。涉及 `workerReady`、协议、能力或版本的修改，必须同时提供数据库迁移或管理端更新方案。

## 9. 已确认的目标领域模型（不属于 2026-07-27 快照）

- **Vendor 是真实运营方。** 以谁签发凭据、向谁结算、由谁提供余额和支持为判定依据；不能用协议名、上游品牌或“网关”渠道类型代替 Vendor。
- **Provider 是可配置的服务入口。** Provider 可以复用协议，但不会因为兼容某协议而自动归属于该协议对应的品牌。
- **Protocol 表达兼容契约。** `openai_images` 等兼容格式属于 Protocol，不是厂商身份。
- **Gateway 表达 Channel Kind。** `vendorKind=gateway` 说明第三方网关渠道，不应产生 `openai_gateway` 这类虚拟厂商。
- **`upstreamVendor` 表达上游品牌。** 公开页面可以据此把第三方入口归入“OpenAI 生态”等展示组，但账户、计费、余额、删除级联和故障归属仍以真实 Vendor 为准。

目标映射中，`ofox_openai_images` 的 Vendor 为 `ofox`；`openai_images_gateway` 等通用兼容 Provider 的账户按各自真实运营方归属。OpenAI 官方账户才归 `openai`，不得仅因使用 OpenAI 兼容格式就把第三方网关并入 OpenAI。

迁移历史 `openai_gateway` 数据时，必须先识别每个账户的真实运营方。无法识别的账户应中止迁移并要求人工指定，不能猜测为 `openai`，也不能静默放入兜底虚拟厂商。

该目标模型的决策理由见 [ADR-0001：按真实运营方界定模型厂商](./adr/0001-model-vendor-boundary.md)，规范术语见根目录 [`CONTEXT.md`](../CONTEXT.md)。

## 10. 新 Provider 接入检查清单

1. 确认签发凭据并承担计费责任的真实运营方，以其作为厂商目录 code；不得用兼容协议、上游品牌或 `gateway` 渠道类型代替 Vendor。
2. 在 `model-providers.yml` 增加唯一 Provider code、能力、协议、上游厂商和鉴权/模型参数 schema；未接通前显式设 `workerReady: false`、`adapterInstalled: false`。
3. 文本 Provider 更新 Agent `ChatModelFactory`/`ModelClient`；媒体 Provider 更新 Worker Registry、目标 handler 和 client，不能只加 YAML。
4. 若使用共享协议，优先复用 `openai_chat`、`openai_images` 等协议适配器，并记录厂商特有的请求/响应差异。
5. 对已存在的数据库行提供更新迁移，因为 `DataInitializer` 不会用 YAML 覆盖它。
6. 需要余额查询或配置探活时，分别实现 Balance Adapter 或 Connectivity Probe；不要把它们当作执行适配器完成的证据。
7. 增加与风险匹配的定向测试，检查能力路由、鉴权字段脱敏、异步轮询和错误归一化。
8. 部署后经授权执行一次受控真实请求，并核对任务快照、目标路由和最终产物；在此之前只标记“代码已接线，生产未验收”。

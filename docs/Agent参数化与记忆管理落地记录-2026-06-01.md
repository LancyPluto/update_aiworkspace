# Agent 参数化与记忆管理落地记录

更新时间：2026-06-01

## 本轮目标

把 Agent 从实验性能力继续推进到可运营状态：

- 后台可调整关键 Agent 运行参数，新 run 生效，不打断正在运行的任务。
- 长期记忆继续使用内置 MySQL 检索与候选审核，不引入外部 memory provider。
- 产品工具调用、额度校验、任务派发仍走后端受控链路。
- 管理后台能查看、筛选、编辑和审核 Agent 记忆。

## 已落地能力

### Agent 参数后台化

后台「设置」新增 Agent 参数入口，覆盖四类配置：

- 基础提示词：`agent.system_prompt`、`agent.deep_agents_system_prompt`
- 路由策略：是否启用 LLM 路由、路由提示词、最低置信度、规则回退
- 记忆策略：自动保存、检索条数、启用类型、写入/检索提示词、记忆工具循环、合并阈值
- 运行限制：最大模型调用次数、最大工具调用次数、历史消息数、工具超时、轮询间隔、产品工具循环

后端新增 `AgentRuntimeSettings` 与 run context 下发字段。`agent-service` 优先使用后端下发值，缺省再回退环境变量。

### 并发安全与运行事件

Runtime settings 已改为每次 run 独立读取：

- 不再把后台参数写回共享的 `BudgetGuard`、`BackendToolBridge` 或产品工具循环实例。
- 工具轮询间隔、图片/视频/普通工具超时、流式进度转发均按当前 run 读取。
- 新增 `runtime_settings.applied` 事件，后台可看到本次 run 实际生效的预算、超时和工具循环参数。

### 产品工具循环

`agent-service` 增加 product-tool-first 路径：

- 将后端可见工具暴露为受控模型 tool definitions。
- 模型只选择工具和参数，实际执行仍通过 `BackendToolBridge` 创建后端任务。
- 工具别名和选择结果为本次 run 私有，避免并发 run 互相污染。
- 输出模态不匹配会拒绝并回退到原路由。

### 任务额度兜底

合并 dev 后补齐任务派发前额度检查：

- 后端新增 `TaskCreditDispatchService`，在 Agent/任务派发前按工具和模型配置估算额度。
- `agent-service` 新增 `task_dispatch_credit.py`，在本地预算内提前拒绝明显超预算的工具调用。
- 最终冻结、结算、释放仍由后端 `CreditService` 负责。

### 记忆管理与安全

后台新增「记忆管理」能力：

- 按状态、类型、用户、工作区、关键词筛选记忆。
- 支持编辑、删除、候选转正、候选拒绝。
- 支持批量转正、批量拒绝、批量删除。

记忆类型统一为 `workspace_fact`，继续兼容旧 `project_knowledge`。

记忆写入安全扫描增强：

- 拦截 prompt injection 类内容。
- 拦截隐形控制字符。
- 拦截 API Key、token、password、`sk-`、AWS Key 等密钥样式。
- 拒绝时记录 `memory.rejected`，并写入明确原因。

## 接口与数据

新增管理端记忆接口：

- `GET /api/admin/v1/agent/memory`
- `PUT /api/admin/v1/agent/memory/{id}`
- `POST /api/admin/v1/agent/memory/{id}/approve`
- `POST /api/admin/v1/agent/memory/{id}/reject`
- `DELETE /api/admin/v1/agent/memory/{id}`

设置接口继续复用 `/api/admin/v1/settings`，并支持恢复 `agent` 默认配置。

数据库初始化和 SQL 已同步 Agent 记忆字段与 FULLTEXT 检索索引。

## 注意事项

- v1 继续使用 MySQL FULLTEXT + 子串降级 + context pack，不引入向量库。
- 外部 memory provider 仅保留扩展方向，暂不接入。
- 参数调整只影响新 run。
- 模型供应商、模型名、Base URL、API Key 仍在「大模型接入」维护。
- 本地 `.venv` 若损坏，`scripts/start-dev.ps1` 会尝试安全重建。

# AI Tool Market 当前阶段项目文档

更新时间：2026-06-02  
项目阶段：MVP 后期到扩展期  

## 1. 项目定位

AI Tool Market 是一个面向中文用户的 AIGC 工具市场与运营平台。当前产品不是单点生成工具，而是围绕“工具配置、任务执行、算力计费、Agent 编排、结果复用、社区曝光”形成闭环。

核心商业目标：

> 把中文 AIGC 工具、任务执行、算力计费、Agent 编排和作品社区闭环成可运营、可计费、可复用的平台。

当前阶段的第一优先级不是扩功能，而是稳定主链路：

```text
用户选择工具
-> 创建任务
-> 冻结算力
-> Worker 执行
-> 结果回写
-> 前端展示
-> 发布社区
-> 同款创作回流
-> 再次创建任务和消费
```

## 2. 系统模块职责

| 模块 | 技术栈 | 当前职责 | 边界要求 |
| --- | --- | --- | --- |
| `backend` | Spring Boot 3 / Java 17 | 用户、鉴权、工具、任务、额度、计费、社区、PPT BFF、Agent run 持久化、内部接口 | 全平台事实源 |
| `user-web` | Vue 3 / Vite | 用户端工具市场、工作台、Agent 入口、任务结果、素材库、社区、PPT 工作台、充值 | 只消费后端接口，不自行推导业务状态 |
| `admin-frontend` | Next.js / React | 管理后台：工具、模型、Prompt、工作流、计费、用户、社区、Agent 诊断、系统设置 | 运营配置入口，不承担业务事实源 |
| `agent-service` | FastAPI / Python | Agent 编排、意图路由、受控工具调用、文件解析、记忆候选、运行事件回传 | 只编排，不结算额度，不拥有最终任务状态 |
| `worker` | Python | 队列消费、模型调用、长任务轮询、媒体落盘、结果回写 | 只执行，不决定业务权限和最终计费 |
| `engines/banana-slides` | Flask/Python | PPT 生成引擎：大纲、描述、出图、导出 | 内部引擎，用户不直接访问 |
| `deploy` | Docker Compose / Scripts | 本地和服务器部署编排 | 不保存真实密钥 |
| `sql` | SQL scripts | 数据表、seed、修复脚本 | 需要线性迁移治理 |

## 3. 当前核心业务能力

### 3.1 工具市场与任务执行

当前主线接口：

- 用户工具列表：`GET /api/v1/tools`
- 工具详情：`GET /api/v1/tools/{toolCode}`
- 创建任务：`POST /api/v1/tasks`
- 任务状态：`GET /api/v1/tasks/{taskId}/status`
- 任务详情：`GET /api/v1/tasks/{taskId}`
- 任务事件流：`GET /api/v1/tasks/{taskId}/events`

业务原则：

- 工具配置由后端和管理端维护。
- 任务创建必须经过额度检查和冻结。
- Worker 通过内部接口获取执行上下文并回写状态。
- 任务结果展示以后端 `contentJson` 和媒体落盘 URL 为准。

### 3.2 算力与计费

当前能力：

- 账户余额
- 算力流水
- 使用日志
- 充值套餐
- 自定义微信充值
- 微信/支付宝支付配置
- Mock 支付开发入口

当前风险：

- Mock 支付必须限制在本地和测试环境。
- 长任务失败、超时、死信必须有冻结额度释放或对账策略。
- 模型价格和实际扣费必须绑定到后端事实源。

### 3.3 Agent 编排

当前能力：

- Agent session / message / run
- SSE 事件流
- 工具调用确认
- 后端可见工具桥接
- 工作区记忆
- 文件解析
- 模型配置与运行参数

边界规则：

- Spring Boot 拥有用户、会话、运行、工具、额度、持久化和审计。
- Agent Service 只读取运行上下文、做意图路由、调用允许的工具、回传事件。
- Agent 不能绕过后端直接创建不可审计的任务。

### 3.4 Worker 多模态执行

当前能力：

- 文本生成
- 图片生成
- 视频生成
- 语音合成
- 数字人视频
- 多 Provider 客户端适配
- 生成媒体落盘
- Redis/RabbitMQ 消费入口

边界规则：

- Worker 不拥有用户权限判断。
- Worker 不自行结算额度。
- Worker 必须通过后端内部接口获取执行上下文。
- Worker 回写必须幂等。

### 3.5 社区与素材复用

当前能力：

- 社区发现页
- 社区作品详情页
- 创作者公开主页
- 灵感收藏夹
- 点赞、收藏、同款
- 后台审核、精选、置顶、打标
- Prompt 可见性控制

产品原则：

- 社区不是泛论坛。
- 社区的商业价值是案例发现、Prompt 学习和同款创作回流。
- 当前不做评论、关注、私信、复杂推荐。

### 3.6 PPT 工作台

当前能力：

- 后端 BFF 代理 banana-slides 引擎
- 创建项目
- 生成大纲
- 生成描述
- 生成图片
- 导出 PPT/PDF/可编辑 PPT
- 管理端同步引擎设置

边界规则：

- 用户不直接访问 banana-slides。
- 后端负责鉴权、额度、项目绑定和代理。
- legacy `ppt-workflow` marker 只应作为迁移期兼容，不能继续扩展。

## 4. 数据与接口事实源

当前保留主线：

- `/api/v1/tools`
- `/api/v1/tasks`
- `/api/v1/credits`
- `/api/v1/agent/*`
- `/api/v1/community/*`
- `/api/v1/ppt/*`
- `/api/admin/v1/*`
- `/api/internal/v1/*`

需要标记淘汰：

- `/api/v1/ai-tools`
- `/api/admin/ai-tools`
- `/api/admin/upload-icon`
- PPT legacy `ppt-workflow` marker
- 缺 `toolCode` 的 PPT 工具兜底
- 生产可达的 mock payment 路径

SQL 治理要求：

- schema migration、seed、repair 分目录或至少命名分层。
- 迁移编号全局唯一。
- 修复脚本必须声明是否幂等。
- 测试 schema 必须定期与迁移脚本对齐。

## 5. 安全边界

当前必须承认的风险：

- `.env` 已被 git 跟踪且当前有本地修改。
- `WXcert/*.pem` 已被 git 跟踪。
- `_remote.py` 和 `_fix_remote.py` 已被 git 跟踪。
- 后端生产模式校验默认 `JWT_SECRET` 和 `INTERNAL_API_TOKEN`，但 Agent/Worker 仍有默认值。
- 管理端存在开发 mock 绕过登录。
- Mock 支付入口需要环境隔离。

安全规则：

- 真实密钥、证书、远程凭据不得进入 git。
- 所有服务生产环境必须拒绝默认内部 token。
- 内部接口必须使用签名或等价强认证。
- 用户上传、Prompt 快照、媒体 URL 和社区公开内容必须执行敏感信息过滤。

## 7. 当前已知风险

1. 安全风险：真实环境文件和证书被 git 跟踪，必须立即处理。
2. 架构风险：后端、Agent、Worker 边界有重叠，容易形成多事实源。
3. 交付风险：巨型服务和巨型页面降低改动速度。
4. 数据风险：SQL 迁移编号重复，环境结构可能漂移。
5. 计费风险：长任务、失败回写、死信重放和冻结释放必须持续验收。
6. 产品风险：功能入口过多，容易削弱工具消费主链路。
7. 运营风险：管理后台配置面太宽，高风险配置缺少足够的测试和回滚保护。

## 8. 当前阶段原则

- 稳定主链路优先。
- 后端事实源优先。
- 安全治理优先。
- 减少兼容分支优先。
- 先可审计，再智能化。
- 先可计费，再扩功能。

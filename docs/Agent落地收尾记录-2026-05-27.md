# Agent 落地收尾记录

更新时间：2026-05-27

## 今日结论

今天 Agent 链路已经达到“可继续按网站产品形态适配”的阶段，可以先点到为止。当前重点不是继续堆复杂 Agent 框架，而是把现有工具市场主链路稳定下来，让 Agent 成为工具选择、参数补全、任务创建和结果总结的编排层。

## 当前 Agent 模型来源

Agent 页面左侧/输入框模型选择读取的是后台模型配置表中的 Agent 可用模型：

- 后台模型配置表：`agent_model_configs`
- 关键字段：`agent_enabled`
- 前台接口：`GET /api/v1/agent/model-configs`
- 运行保存：`agent_runs.model_config_id`
- agent-service 执行时优先使用 run context 中的 `modelConfig`

这里的模型只负责 Agent 自己的理解、规划、对话和工具编排。

## 工具模型边界

“作为 Agent 模型”不是“给所有工具执行用的模型”。AI 工具执行时仍然读取工具自身配置：

- 工具表：`ai_tools`
- 工具模型字段：`ai_tools.model_config_id`
- 工具执行链路：Agent 选择工具后，通过 backend tool/task 链路创建任务
- Worker 或工具执行器按工具自身绑定模型、模板和 provider 配置调用模型

因此需要保持两条配置线：

| 配置线 | 作用 |
| --- | --- |
| Agent 可用模型 | Agent 自己聊天、规划、路由、编排 |
| AI 工具绑定模型 | 图片、视频、文本、语音等工具真正执行时使用 |

## Agent 可读取工具范围

Agent 当前从 backend 获取在线 AI 工具描述：

- 来源：`ai_tools`
- 默认过滤：在线、未删除工具
- 扩展开关：`agent_tool_descriptor_extensions.agent_enabled`
- 当前上限：放宽到 1000 个在线工具，避免只读到前 100 个

短期建议仍然只让用户侧 Agent 读取在线工具。草稿、下线工具可以留给管理端调试，不应该直接暴露给普通用户。

## 系统提示词配置

Agent 系统提示词已经从 agent-service 硬编码改为后台可配置：

- 普通 Agent 提示词：`system_settings.agent.system_prompt`
- Deep Agents 提示词：`system_settings.agent.deep_agents_system_prompt`
- 后台页面：`/prompts` 已调整为 Agent 配置页
- 默认值由启动初始化和 SQL 脚本兜底写入

运行时 backend 会把提示词下发到 run context，agent-service 再追加在线工具清单。这样管理员可以在后台调整 Agent 人设、工具边界和回复策略，而不需要改代码。

## 已修复的关键稳定性问题

- 增加 Agent 上下文字段和数据库 schema guard，避免新增字段缺失导致运行中断。
- Agent 模型选择支持前端选择，并保存到 run。
- 取消每条消息发送前的模型联网预检，避免用户对话被测试接口阻塞。
- agent-service 调 backend internal API 时禁用环境代理，避免 localhost 请求被代理导致 502。
- 增加 agent-service 后端调用错误日志，方便定位 context/fail 回调失败。
- Agent 页面增加模型生成中的加载反馈。
- `/prompts` 后台页改为 Agent 配置页，可查看在线工具数量、工具模型绑定情况并保存系统提示词。

## 当前仍需克制的点

agent-service 可以保留，但暂时不建议让它膨胀成第二套业务后端。商业化多用户系统里，事实源仍然应该是 backend：

- 用户、权限、算力、订单、审计归 backend。
- 工具配置、任务状态、模型计费归 backend/worker 主链路。
- agent-service 只做 Agent runtime、上下文处理、规划和编排。
- 后续如果并发压力上来，再把 agent-service 做成独立 worker pool、队列消费和水平扩容。

## 后续网站适配建议

下一阶段可以围绕正式网站体验做轻量适配：

1. Agent 首屏更像“工具推荐与执行入口”，减少实验性事件噪音。
2. 对普通用户隐藏过多运行细节，只保留“正在分析、已选择工具、正在生成、完成”这类可理解状态。
3. Agent 工具推荐需要展示工具名、用途、预计算力和确认按钮。
4. 真正执行图片/视频/文本工具时，结果应回到现有任务和素材库体系。
5. Prompt 管理页继续演进为 Agent 配置中心，后续可增加“工具选择策略”“是否自动调用”“默认确认策略”等配置。

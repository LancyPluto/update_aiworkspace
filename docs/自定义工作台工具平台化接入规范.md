## 1. 要解决什么问题

### 1.1 两类工具，两条链路

| 类型 | 用户入口 | 后端链路 | 典型能力 |
| --- | --- | --- | --- |
| **标准任务工具** | `/tools/:id/use` | 动态表单 → `ai_tasks` → Redis → **worker** | 文案、单次生图、一次提交一次结果 |
| **自定义工作台工具** | **`customUiRoute`（配置驱动）** | 登录用户 → **BFF 模块** → 外部引擎/服务 | PPT 多步项目、数字人、AI 漫剧… |

当前问题不是「PPT 只能有一个 `toolCode`」，而是：

- 入口写死 `toolCode === 'banana_ppt_generator'`；
- 以后上 **数字人、AI 漫剧** 等同样不能走 `/tools/:id/use` 的工具时，会被迫继续堆 `if (toolCode === '...')`；
- **每加一个工具类型就要改 ToolDetail、路由、后端分支** → 无法热插拔。

### 1.2 设计原则

1. **`toolCode` 只标识工具实例**（上架条目），不标识集成方式。  
2. **`integrationMode` 标识集成方式**（走标准任务还是哪种工作台）。  
3. **新增工具类型 = 新增插件（Plugin）+ 运营配置**，不改超市主链路核心代码。  
4. **PPT 是第一个已落地的插件**，不是架构的全部。

## 2. 目标与非目标

### 2.1 目标（热插拔）

| 层级 | 目标 |
| --- | --- |
| **用户端** | ToolDetail 统一：`非 STANDARD_TASK` → 跳 `customUiRoute`；工作台路由通用（如 `/tools/:toolCode/workspace/*`），页面按 `pluginId` 懒加载 |
| **后端** | `ToolIntegrationRegistry` 按 `integrationMode` 分发；各插件独立包（`ppt`、`digital-human`…），共用鉴权/算力/用户 |
| **管理端** | 工具编辑页按 `integrationMode` 挂载配置面板组件；新插件注册面板，不改工具列表 CRUD |
| **配置** | `ai_tools.config_note` 内统一 `tool-integration` 契约；插件扩展字段放子对象（如 `ppt`） |
| **运营** | 新工具 = 后台新建 `tool_code` + 填集成配置 + 上架，**零发版改 if**（仅新插件首次需开发） |

### 2.2 非目标

- 不把自定义工作台强行并入 `ai_tasks` / worker。  
- 不做「任意 URL 即可挂」的无约束插件市场（插件须代码注册，防安全风险）。  
- 一期不要求所有插件共用同一套 UI 框架（允许各插件自研 Vue 页，但入口/路由/契约统一）。

## 3. 架构总览

```text
                    ┌──────────────────────────────────────┐
                    │           ai_tools 配置               │
                    │  <!-- tool-integration:{...} -->     │
                    │    integrationMode, customUiRoute,   │
                    │    apiPrefix, pluginId, [plugin扩展]   │
                    └──────────────────────────────────────┘
                                      │
          ┌───────────────────────────┼───────────────────────────┐
          ▼                           ▼                           ▼
   integrationMode              integrationMode              integrationMode
   STANDARD_TASK               PPT_WORKSPACE                DIGITAL_HUMAN_*
   (缺省)                      plugin: ppt                   plugin: digital-human
          │                           │                           │
          ▼                           ▼                           ▼
   /tools/:id/use              /api/v1/ppt/*                /api/v1/digital-human/*
   ai_tasks + worker           PptProjectService            XxxProjectService
```

**热插拔含义**：主工程只依赖 **`ToolIntegrationDescriptor` + Registry**；新能力通过 **注册插件 Bean / 前端 module map** 接入，而不是在 `ToolDetail.vue` 里加第三个、第四个 `toolCode`。

## 4. 统一配置契约：`tool-integration`

与 Chat 的 `<!-- ai-tool-ui:... -->`、PPT 的 `<!-- ppt-workflow:... -->` **并存**；平台级入口以 **`tool-integration`** 为准（解析优先级高于单独 ppt-workflow）。

### 4.1 标记格式

```text
<!-- tool-integration:{JSON} -->
```

可与其他说明文字、`ppt-workflow` 旧块同存于 `config_note`；迁移期允许 **仅存在 ppt-workflow 时由后端自动推导 integration**（见 §9）。

### 4.2 平台层 JSON Schema

```json
{
  "integrationMode": "PPT_WORKSPACE",
  "pluginId": "ppt",
  "customUiRoute": "/tools/banana_ppt_generator/workspace",
  "apiPrefix": "/api/v1/ppt",
  "displayName": "PPT 工作台",
  "engine": {
    "type": "banana-slides",
    "baseUrl": "http://127.0.0.1:5000"
  },
  "ppt": {
    "creationTypes": ["idea", "outline", "descriptions"],
    "steps": [{ "code": "CREATE", "name": "创建", "credits": 5, "enabled": true }],
    "features": { "renovation": true },
    "textModelConfigId": 12,
    "imageModelConfigId": 15
  }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `integrationMode` | 是 | 集成类型枚举（见 §5） |
| `pluginId` | 是 | 前后端插件注册名，如 `ppt`、`digital-human` |
| `customUiRoute` | 推荐 | 「立即使用」目标；缺省 `/tools/{toolCode}/workspace` |
| `apiPrefix` | 推荐 | 该插件 BFF 前缀，供前端 `api` 封装与网关路由 |
| `engine` | 视插件 | 外部引擎类型与 BaseUrl；缺省走插件全局配置 |
| `{pluginId}` 子对象 | 视插件 | 插件私有配置（原 `ppt-workflow` 内容迁入 `ppt`） |

### 4.3 用户工具详情 API 增量

`GET /api/v1/tools/{toolCode}` 在现有字段上增加（或复用扩展对象）：

```json
{
  "toolCode": "banana_ppt_generator",
  "integration": {
    "integrationMode": "PPT_WORKSPACE",
    "pluginId": "ppt",
    "customUiRoute": "/tools/banana_ppt_generator/workspace",
    "apiPrefix": "/api/v1/ppt",
    "ppt": { }
  }
}
```

**规则**：只要 `integration.integrationMode !== STANDARD_TASK`，前端 **禁止** 跳转 `/tools/:id/use`。

## 5. `integrationMode` 与插件注册表

### 5.1 枚举（可扩展）

| integrationMode | pluginId | 说明 | 状态 |
| --- | --- | --- | --- |
| `STANDARD_TASK` | — | 默认；走动态表单 + worker | 已上线 |
| `PPT_WORKSPACE` | `ppt` | 多步 PPT 项目 + banana 引擎 | 后端已有，待平台化 |
| `DIGITAL_HUMAN_WORKSPACE` | `digital-human` | 数字人（示例） | 规划 |
| `COMIC_WORKSPACE` | `comic` | AI 漫剧（示例） | 规划 |

新增类型时：**在 Registry 注册一行 + 实现插件模块**，不改 `ToolServiceImpl` 主流程。

### 5.2 后端 Registry（热插拔核心）

```java
public interface ToolIntegrationPlugin {
    String integrationMode();
    String pluginId();
    /** 校验 config 子对象、补默认值 */
    void validateIntegration(AiTool tool, ToolIntegrationConfig config);
    /** 用户详情里附带的扩展（可选） */
    Object userDetailExtension(AiTool tool, ToolIntegrationConfig config);
}

@Component
public class ToolIntegrationRegistry {
    private final Map<String, ToolIntegrationPlugin> byMode;
    public ToolIntegrationPlugin require(String integrationMode) { ... }
}
```

- 各插件 `@Component` 实现 `ToolIntegrationPlugin`（如 `PptIntegrationPlugin`），Spring 自动注入 Registry。  
- **禁止**在 Controller 里 `switch (toolCode)`。  
- Admin 配置保存：Registry → 对应插件 `validate` + `onSave`（如同步引擎）。

### 5.3 前端 Registry（热插拔核心）

```ts
// user-web/src/integrations/registry.ts
export const integrationPlugins: Record<string, () => Promise<IntegrationPluginModule>> = {
  ppt: () => import("./ppt"),
  "digital-human": () => import("./digital-human"),
}

export function resolveUseRoute(tool: ToolDetail): string {
  const i = tool.integration
  if (!i || i.integrationMode === "STANDARD_TASK") {
    return `/tools/${tool.id}/use`
  }
  return i.customUiRoute ?? `/tools/${tool.toolCode}/workspace`
}
```

- **ToolDetail**：只调 `resolveUseRoute(tool)`，不出现 `banana_ppt_generator`。  
- **路由**：一条泛化路由  
  `path: "/tools/:toolCode/workspace/:pathMatch(.*)*"`  
  进入 `WorkspaceHost.vue`，按 `pluginId` 动态 `import()` 对应插件布局。  
- 新插件：新增 `src/integrations/{pluginId}/` 目录 + registry 一行。

### 5.4 管理端 Registry

```ts
// admin-frontend/lib/integrations/registry.ts
export const adminConfigPanels: Record<string, Component> = {
  ppt: PptWorkflowPanel,
  "digital-human": DigitalHumanConfigPanel,
}
```

工具编辑 Dialog：根据 `integration.integrationMode` 渲染对应 Panel；保存调插件声明的 admin API（如 `PUT .../ppt-workflow`）。

## 6. 标准链路 vs 自定义链路（行为对比）

| 环节 | STANDARD_TASK | 自定义工作台（任意 integrationMode） |
| --- | --- | --- |
| 列表/详情展示 | 估计算力、字段 schema | 估计算力 + **integration 扩展**（步骤说明等） |
| 立即使用 | `/tools/:id/use` | **`customUiRoute`** |
| 创建「任务」 | `POST /api/v1/tasks` | **`POST {apiPrefix}/...`**（插件定义） |
| 算力 | 任务冻结/结算 | 插件内分步扣费（如 `PPT_STEP`） |
| Worker | 使用 | **不使用** |
| 新工具上线 | 配 fields + model | 配 **tool-integration** + 插件配置子对象 |

## 7. 插件开发规范（新工具接入清单）

新增如 **数字人** 时，按下列清单交付，**无需改** ToolDetail / 标准 Task 代码。

### 7.1 后端

- [ ] 新建包 `.../digitalhuman/`（或 `integration/digitalhuman`）
- [ ] 实现 `ToolIntegrationPlugin`（`integrationMode` + `validate`）
- [ ] 暴露 BFF：`/api/v1/digital-human/*`（`apiPrefix` 一致）
- [ ] 用户数据表（若需要）带 `tool_id`、`user_id`
- [ ] 注册到 `ToolIntegrationRegistry`（Spring 自动）
- [ ] Admin API：`/api/admin/v1/tools/{toolId}/digital-human-config`（可选命名）
- [ ] 单元测试 + 不影响 `TaskApiTest` / worker 回归

### 7.2 user-web

- [ ] `src/integrations/digital-human/`：`routes.ts`、`api.ts`、`Workspace.vue`
- [ ] `registry.ts` 增加 `digital-human` 懒加载
- [ ] 确认 `resolveUseRoute` 对 `DIGITAL_HUMAN_WORKSPACE` 生效

### 7.3 admin-frontend

- [ ] `DigitalHumanConfigPanel.tsx` + registry
- [ ] 工具表单可选设置 `integrationMode`（或选模板一键写入 `tool-integration`）

### 7.4 运营配置

- [ ] `tool_code` 唯一（如 `acme_digital_human`）
- [ ] `config_note` 写入完整 `tool-integration` JSON
- [ ] 上架；用户详情 `integration` 非空即可用

## 8. 附录 A：PPT 插件（首个落地插件）

现有 `ppt` 模块视为 **`pluginId=ppt`** 的实现，从「全站单工具」迁到平台契约：

| 项 | 迁移 |
| --- | --- |
| 配置 | `ppt-workflow` JSON 迁入 `tool-integration.ppt`；解析器同时兼容旧标记 |
| 入口 | 删除 `PptConstants.TOOL_CODE` 分支；改 `integrationMode=PPT_WORKSPACE` |
| 创建项目 | `POST /api/v1/ppt/projects` body 带 **`toolCode`** |
| 引擎 | `engine.baseUrl` per-tool；`PptEngineClientFactory` |
| 绑定表 | `ppt_project_bindings.tool_id` 已满足多实例 |

详细 API 与步骤码见 [PPT生成工具接入-后端开发文档.md](./PPT生成工具接入-后端开发文档.md)。

## 9. 附录 B：迁移与兼容

### 9.1 存量 `banana_ppt_generator`

1. 若仅有 `<!-- ppt-workflow:... -->`、无 `tool-integration`：  
   后端 `ToolIntegrationResolver` 自动推导：

   ```json
   {
     "integrationMode": "PPT_WORKSPACE",
     "pluginId": "ppt",
     "apiPrefix": "/api/v1/ppt",
     "customUiRoute": "/tools/{toolCode}/workspace",
     "ppt": { /* 原 workflow 对象 */ }
   }
   ```

2. `execution_handler` 仍为占位值，**worker 不消费** PPT 工具。

### 9.2 禁止写法（代码评审）

```java
// ❌
if ("banana_ppt_generator".equals(tool.getToolCode())) { ... }

// ✅
if (integrationRegistry.isCustomWorkspace(tool)) { ... }
```

```ts
// ❌
if (tool.toolCode === "banana_ppt_generator") router.push(...)

// ✅
router.push(resolveUseRoute(tool))
```

## 10. 实施阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **P0** | `tool-integration` 解析；`ToolDetailResponse.integration`；`resolveUseRoute` | 配置 PPT 工具后不再依赖 toolCode if |
| **P1** | 后端 `ToolIntegrationRegistry` + PPT 插件适配；去掉 `TOOL_CODE` 硬编码 | 两个 PPT tool_code 可并存 |
| **P2** | user-web `WorkspaceHost` + ppt 插件懒加载；泛化路由 | 数字人插件可抄 ppt 目录结构接入 |
| **P3** | admin 配置 Panel registry + PPT Panel | 运营只改配置可上新 PPT 实例 |
| **P4** | 第二个插件（数字人或漫剧）端到端验证热插拔 | 不改 ToolDetail 核心文件 |

建议顺序：**P0 → P1 → P2** 打通 PPT；再用 **P4** 验证「加工具类型不改主链」。

- [ ] 任意 **STANDARD_TASK** 工具：详情 → use → 任务 → 结果 不变
- [ ] **PPT_WORKSPACE** 工具：不进 `/tools/:id/use`，进 `customUiRoute`

- [ ] 模拟 `DIGITAL_HUMAN_WORKSPACE` 配置后，仅加载 digital-human 插件、不调 ppt API
- [ ] 未注册 `integrationMode` 的配置保存失败，错误信息明确
- [ ] Agent、Chat、任务列表与插件无关

## 12. 评审待决

1. **配置块命名**：统一 `tool-integration` 还是数据库新增 `integration_mode` 列？（列更利于检索，块更利于热插拔扩展）

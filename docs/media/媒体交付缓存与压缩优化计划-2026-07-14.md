# 媒体交付缓存与压缩优化计划

## 目标

- 公共内容哈希媒体经 OSS/CDN 和浏览器长期缓存，私有媒体保持鉴权和短缓存。
- 图片按展示尺寸使用 OSS WebP 派生，派生失败自动回退原图。
- 视频预览和封面失败不影响原视频及生成任务成功状态。
- 媒体持久化、派生和前端回退具备低基数指标与后台配置诊断。

## 缓存契约

| 资源 | Cache-Control | 说明 |
| --- | --- | --- |
| 公共内容哈希资源 | `public,max-age=31536000,immutable` | URL 内容不可变，可长期缓存 |
| 私有资源 | `private,max-age=3600` | 继续通过权限校验和签名 URL 访问 |
| 历史或非哈希资源 | `public,max-age=300,must-revalidate` | 避免旧固定路径长期污染 |

生产 CDN 必须保留 `x-oss-process` 查询参数并将其纳入缓存键。公共 Bucket 的 CORS/CDN
响应应允许浏览器读取必要的资源计时信息；密钥、Bucket 凭据和签名参数不得进入指标。

## 派生规格与回退

- LQIP：32px、WebP、质量 30。
- 列表：320px、WebP、质量 80。
- 标准卡片：640px、WebP、质量 85。
- 详情：1280px、WebP、质量 88。
- 图片：LQIP（可选）→ 尺寸派生图 → 原图 → 占位。
- 视频：OSS 1 秒封面 → 10 秒 480p 预览 → 原视频 → 占位。

非 OSS、Data URL 和不支持处理的外部 URL 不构造虚假的派生路径。每个候选只请求一次，
去重后最多三次。下载始终使用原始资源。

## 观测与维护

- Worker：媒体持久化结果、原始/派生字节、派生耗时、压缩比例和视频预览结果。
- Backend：OSS 存储操作、前端派生成功/回退/最终失败，以及脱敏后的配置健康状态。
- 用户端：按页面、媒体类型、阶段和结果聚合上报，不发送资源 URL。
- 管理端：在系统监控页展示存储、CDN、转换、缓存和私有鉴权配置状态，并链接 Grafana。

## 发布与回滚

先在 staging 开启 `VITE_MEDIA_DELIVERY_OPTIMIZATION`，验证缓存头、缩略图缺失回退、视频
预览缺失回退和核心页面 LCP。生产异常时关闭该开关恢复原图直出；原始文件、缓存元数据
和已生成预览无需回滚。OSS 元数据回填脚本默认 dry-run，只有显式 `--apply` 才写入。

## 外部配置清单

- CDN 缓存键必须包含完整 `x-oss-process` 参数，不得把不同尺寸或质量的派生图合并缓存。
- 公共 OSS/CDN 应保留 `Content-Type`、`Content-Length`、ETag、Cache-Control，并允许 WebP 与视频快照处理。
- 生产可配置 `MEDIA_HEALTHCHECK_URL` 指向代表性的公共内容哈希图片；未配置或 CDN 暂不可用只告警，原图交付不被阻断。
- 私有 Bucket 不得标记为 `public`，签名 URL 有效期维持一小时，签名参数不进入日志和指标标签。

## 实施记录

- 用户端已统一图片候选链和视频预览链，覆盖首页、社区、Dashboard 结果与资产卡；非 OSS 直接使用原图。
- Worker 视频预览改为最多两个并发槽位的后台任务，预览容量不足、FFmpeg 缺失或压缩失败均不延迟原任务结果。
- Backend 已提供聚合媒体事件入口和管理员配置健康接口；页面、媒体类型、阶段与结果均使用固定枚举。
- Nginx 仅对内容哈希 `/generated/` 路径启用一年 immutable，历史路径保持短缓存并重新验证。
- 管理后台和 Grafana 已增加媒体交付状态、回退、派生耗时、存储结果与核心页面 LCP 观测。

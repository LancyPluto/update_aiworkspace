# 工作区整理与上传记录 - 2026-06-09

## 本轮目标

本轮围绕 Agent 附件素材、工具调用可靠性、模型账号配置解耦、工作台图片体验和上传素材持久化做收口，并将规则写入文档，方便后续继续开发时保持一致。

## 关键改动

### Agent 附件与素材

- Agent 上传图片不再默认等同于“文件分析”，生成、改图、参考图等表达会优先进入工具调用路径。
- Agent 素材入口支持上传、多选、素材库复用和最近上传复用。
- 用户消息中的参考图以 `@图片1-...`、`@图片2-...` 形式展示，便于提示词描述“图一/图二”时和实际参数顺序一致。
- 工具自动填参支持多图数组字段，例如 `image`、`images`、`referenceImageUrls` 等；只有单图字段时继续只取第一张，保持兼容。
- 确认调用工具时支持“不再提示”，用户确认后会写入工具偏好，后续同类工具可自动调用。
- 新增“智能程度”选项，高智能模式会扩大上下文和校验预算，提交前更重视附件、记忆和最近结果。

### 用户上传素材持久化

- 新增 `user_upload_assets` 表，作为用户上传素材的真实持久化索引。
- `/api/v1/tool-upload` 上传文件后会写入 `user_upload_assets`，返回 `assetId/fileId/url/name/contentType/size`。
- 新增素材列表和删除接口：
  - `GET /api/v1/upload-assets`
  - `DELETE /api/v1/upload-assets/{assetId}`
- 工作台和 Agent 最近上传统一优先读取 `user_upload_assets`，`localStorage` 仅作为兜底缓存。
- 删除最近上传素材时会软删数据库记录，避免用户换浏览器或刷新后旧素材又出现。

### 工作台表单与图片任务

- 新增 `multi_image` 字段类型，表示多参考图 URL 数组。
- 比例字段收敛为正式控件类型 `aspect_ratio`，按后台 JSON 配置渲染，不在用户端写死比例列表。
- 比例默认值优先使用 `auto`，界面显示“智能”，不得隐式转成 `16:9`。
- 数字范围字段使用 `slider` 控件类型，例如生成数量。
- OpenAI/Ofox Images 参考图编辑会走 `/images/edits`；有参考图时不能误走 `/images/generations`。
- `topUpEditBatch=true` 可配置在厂商账户 `extraAuthJson` 中，用于补齐图片编辑接口返回数量少于请求数量的场景。

### 模型账号配置解耦

- 目标规则：厂商账户维护凭据、Base URL、AK/SK 和执行扩展；模型只绑定账户并声明模型名、能力、价格、是否 Agent 可选。
- 管理后台模型新增/编辑时可选择绑定的 API 账户。
- Worker 执行时应使用后端下发的模型绑定账户和凭据，不再依赖硬编码密钥。
- 后续新增账号或切换额度账号，应优先通过管理后台配置完成。

### Agent UI 收口

- 移除了输入栏里尚未实现的“深度思考”占位按钮。
- 修复“记忆”等按钮文字乱码。
- 工具分类、模型工具标签等 Agent 输入栏文案已统一为正常 UTF-8 中文。

## 数据库与配置

- 新增 SQL：`sql/050_user_upload_assets.sql`
- 后端启动初始化同步确保 `user_upload_assets` 表存在。
- 测试 schema 已同步新增 `user_upload_assets`。
- 账号注销清理流程同步删除 `user_upload_assets` 中该用户记录。

## 后续开发规则

- 数据库变更必须同时更新：
  - `sql/*.sql`
  - `DataInitializer`
  - `backend/src/test/resources/schema-test.sql`
  - 相关 DTO/API 类型和文档
- 前端素材复用不要只依赖 `localStorage`；需要跨会话可见的素材必须进入 `user_upload_assets` 或任务结果素材库。
- 模型供应商凭据不要写死在 Worker 或后端代码中，统一通过厂商账户配置下发。
- 比例、数量、多参考图等工具参数应由后台字段 JSON 驱动，用户端只按控件类型渲染。
- Agent 工具调用失败时，优先检查：
  - 工具是否 `agentEnabled=true`
  - 工具别名是否正确
  - 附件是否有可被 Worker 访问的 URL
  - 模型绑定账号是否有凭据和额度

# AI 执行平台与模型渠道套餐系统后续完整执行规划

日期：2026-05-14

## 目标

在当前 MVP 已能跑通模型渠道套餐、Mock 支付、模型工作台、RabbitMQ 任务队列和管理端运营入口的基础上，继续补齐上线测试到正式商业化所需能力。

本计划按“先上线测试稳定，再逐步商业化增强”的顺序推进。

## 阶段 1：上线测试稳定版

目标：组员通过 Docker 拉取后能稳定启动前后端，用户能测试 AI 工具、模型工作台和基础运营后台。

### P0-1 RabbitMQ 可靠队列运营能力

范围：

- 已增加管理端队列状态查看：主队列、死信队列、消息数量。
- 已增加死信重放接口：管理员可以把 dead queue 中的任务重新投回主任务队列。
- 保留 worker 失败重试和超过次数进入 dead queue 的逻辑。

验收：

- `docker compose config --quiet` 通过。
- worker 消费失败后能重试，超过次数进入 dead queue。
- 管理端可查看 dead queue 数量并触发重放。

### P0-2 Model Gateway 稳定性增强

范围：

- 继续保留自研 Model Gateway，不接 LiteLLM 主链路。
- 对 OpenAI-compatible、Anthropic-compatible 响应做错误归一化。
- 已增加节点失败时的 fallback：同池内下一个可用节点。
- 已记录失败节点 `last_error` 和 `health_status`，成功节点会恢复为 `HEALTHY`。

验收：

- 配置两个同池节点时，第一个失败后能 fallback 到第二个。
- `model_call_logs` 能记录成功/失败和延迟。
- 用户端展示友好的失败信息，不暴露供应商原始密钥或内部配置。

### P0-3 用户工作台体验补齐

范围：

- 优化 SSE 流式输出的错误恢复。
- 增加会话标题自动更新。
- 增加节点繁忙、额度用尽、订阅过期的前端提示。
- 保留停止、重新生成、继续生成、反馈问题。

验收：

- 用户可以完整完成：购买 Mock 套餐、选择模型池、发起对话、停止生成、重新生成、反馈问题。
- 用户不能访问其他人的会话或消息。

### P0-4 管理端运营可用版

范围：

- 套餐、渠道池、节点的新增/编辑表单继续完善。
- 增加节点上下线快捷操作。
- 增加订单、调用日志、反馈列表筛选。
- 节点列表继续脱敏 API Key。

验收：

- 管理员可以人工补号、上下线节点、查看调用日志、查看用户反馈。
- 用户端无法获得真实节点凭证。

## 阶段 2：商业化联调版

目标：为真实用户测试和付费闭环做准备，但仍允许 Mock 支付和开发模式存在。

### P1-1 支付真实接入

范围：

- 接微信支付和支付宝官方 SDK。
- 支持支付创建、回调验签、金额校验、订单幂等、支付流水。
- 保留 MockPayProvider 仅用于 dev/test。

验收：

- 重复回调不会重复发放套餐或算力。
- 金额不一致会拒绝发放权益。
- 支付订单状态机可追踪。

### P1-2 套餐权益精细化

范围：

- 权益编辑表单：模型池权限、小时次数、日次数、并发数。
- 订阅续期策略：同套餐续期叠加有效期，不同套餐并存。
- 用户权益页：展示已购套餐、过期时间、剩余额度、可用模型池。

验收：

- 用户购买后权益立即生效。
- 过期套餐自动失效。
- 超额度和超并发被服务端拦截。

### P1-3 监控与追踪

范围：

- LangSmith 接 Agent LangChain/LangGraph trace。
- 平台继续使用 `model_call_logs` 做业务审计。
- 增加 Prometheus/Grafana 或阿里云监控的部署预留。

验收：

- Agent trace 能关联用户请求或 run id。
- 模型调用日志能按用户、节点、模型、状态查询。

## 阶段 3：生产上线增强版

目标：正式部署到阿里云并支撑真实流量。

### P2-1 Nginx 正式公网入口

范围：

- Nginx 成为唯一公网入口。
- TLS、上传限制、SSE 不缓冲、内部接口公网禁用。
- 开发模式保留直连入口，生产模式禁用。

验收：

- 外部无法访问 `/api/internal/`。
- SSE 响应不被缓冲。
- 上传大小限制生效。

### P2-2 存储抽象和 OSS

范围：

- 增加 `StorageService` 抽象。
- 本地存储和阿里云 OSS 两种实现。
- AI 漫剧、文件上传、Agent 附件统一走 StorageService。

验收：

- dev/test 可用本地存储。
- prod 可切到 OSS。

### P2-3 自动健康检查和容量预警

范围：

- 定时检查模型节点健康。
- 自动标记异常节点。
- 容量不足时管理端预警。

验收：

- 异常节点不再被自动调度。
- 管理端可看到池容量和风险。

## 与组员业务模块的接入规则

- AI 工具、AI 漫剧、长工作流进入 RabbitMQ。
- 普通模型聊天走 Model Gateway 直连，不进 RabbitMQ。
- Agent 编排继续由 LangChain/LangGraph 负责，但模型调用和日志逐步接入 Model Gateway 规范。
- 所有用户侧调用必须做用户隔离、套餐校验、额度校验和日志记录。

## 本批继续执行顺序

1. 管理端节点上下线快捷操作。
2. 用户端额度/订阅提示优化。
3. RabbitMQ 延迟重试和指数退避。
4. 支付回调幂等和真实支付 Provider 对接准备。
5. LangSmith / 基础监控接入预留。

# 图片编辑批量补全配置

## 目标

`openai_images` 类网关在参考图编辑接口中，即使请求参数 `n` 大于 1，也可能只返回 1 张图片。为避免用户选择“生成 2 张”但任务结果只有 1 张，平台支持在管理后台按厂商账户开启补全逻辑。

## 配置位置

管理后台进入统一 API / 厂商账户配置，在“编辑厂商账户”弹窗中开启：

- 图片编辑批量补全：`topUpEditBatch=true`

该配置保存到厂商账户的 `extraAuthJson`，例如：

```json
{
  "topUpEditBatch": true
}
```

如果该账户还需要 AK/SK、代理、超时等扩展参数，可以共用同一个 JSON：

```json
{
  "accessKey": "...",
  "secretKey": "...",
  "topUpEditBatch": true
}
```

## 生效规则

- 只影响 `openai_images` 协议的参考图编辑请求，也就是走 `/images/edits` 的任务。
- 普通文生图 `/images/generations` 不受影响。
- 当上游返回图片数少于用户请求的生成数量时，worker 会追加单张 edit 请求，直到补齐请求数量或达到平台限制。
- 关闭开关后，worker 保持上游原始返回行为。

## 设计约束

- 这是账号级执行选项，不写死在 worker 或单个模型代码中。
- 模型只绑定厂商账户并声明模型名、能力和价格；凭据与执行扩展统一由厂商账户维护。
- 后续新增类似网关兼容参数时，优先放入厂商账户 `extraAuthJson`，再由对应 worker client 读取。

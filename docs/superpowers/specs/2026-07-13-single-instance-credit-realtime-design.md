# 单实例实时余额设计

## 目标

在单个 Spring Boot 后端实例部署下，让同一账号在多台在线设备上的算力余额通常在 2 秒内完成刷新；当实时连接中断或事件丢失时，前端通过重新查询和低频轮询恢复到 MySQL 中的权威余额。

本设计只提升余额展示的实时性，不改变余额冻结、扣减、释放、充值和赠送的事务规则。

## 范围

本期包含：

- 保留 `GET /api/v1/credits/account` 作为余额权威快照接口。
- 新增基于现有登录态鉴权的 `GET /api/v1/credits/events` SSE 接口。
- 后端在算力账户变化后，向当前实例中该用户的全部 SSE 连接发送变化通知。
- 前端收到通知后重新请求账户快照。
- 前端在连接恢复、网络恢复、页面恢复可见时主动校准余额。
- 页面可见期间执行 60 秒低频轮询，作为漏通知兜底。
- 增加后端单元/接口测试和前端行为测试。

本期不包含：

- Transactional Outbox 表和发布器。
- RabbitMQ 跨后端实例广播。
- 多个 backend 实例间的 SSE 连接发现。
- 将 SSE 事件作为余额账本或扣费依据。
- 修改生产环境或部署流水线。

## 架构

### 权威读取

`GET /api/v1/credits/account` 继续从 `credit_accounts` 读取 `balance`、`frozen`、`available`、`totalGranted` 和 `totalConsumed`。前端任何时候都以该响应为最终展示依据。

### 实时通知

新增独立的 `CreditEventStreamService` 管理用户与 `SseEmitter` 的关系。每个用户可以同时持有多个连接，以覆盖同一账号的多台设备和多个标签页。

SSE 建立后发送 `connected` 事件；算力变化后发送：

```json
{
  "type": "CREDIT_ACCOUNT_CHANGED",
  "occurredAt": "2026-07-13T15:30:21+08:00"
}
```

事件不携带可直接入账的余额值。前端收到 `CREDIT_ACCOUNT_CHANGED` 后合并短时间内的重复通知，并重新调用账户 GET。

### 变化触发边界

通知必须覆盖 `CreditServiceImpl` 中所有实际改变账户数值且事务成功提交的路径，包括：

- 冻结可用算力。
- 成功结算并扣减余额。
- 失败、取消或超时后释放冻结算力。
- 直接扣减。
- 普通充值到账。
- 会员算力到账。
- 赠送算力到账。
- 邀请奖励到账。

通知必须在事务提交后执行。事务回滚时不得发送变化事件。实现采用 Spring 的事务同步回调；没有活动事务时可立即通知。

单次业务操作可能包含多个余额写入或重复回调。SSE 允许出现重复通知，因为通知只触发幂等的 GET 查询；前端仍需做短时间合并以控制请求量。

## SSE 连接生命周期

- 使用现有 `AuthInterceptor` 解析 HttpOnly Cookie；保留当前 Bearer JWT 兼容行为，但浏览器默认依赖 Cookie。
- 响应类型为 `text/event-stream`，并设置禁止中间缓存与代理缓冲的响应头。
- 每个 emitter 注册 completion、timeout 和 error 回调，确保从内存连接表移除。
- 服务端使用有限超时，浏览器断线后由 `EventSource` 自动重连。
- 每个用户限制最多 10 个实时连接；超过限制时关闭最旧连接，防止异常客户端无限占用内存。
- 连接表只存在当前 Java 进程内存。后端重启时连接全部断开，浏览器自动重连并重新 GET 校准。

## 前端数据流

`AppShell` 继续持有全局 `credit` 状态，并通过一个专用 composable 管理实时刷新：

1. 登录态建立后立即 GET 账户快照。
2. 创建同源 `EventSource('/api/v1/credits/events')`。
3. 收到变化事件后，在 200 毫秒窗口内合并事件并 GET。
4. SSE `open` 或重连后 GET，弥补断线期间的变化。
5. `online` 事件触发 GET。
6. 页面由隐藏恢复为可见时 GET。
7. 页面可见期间每 60 秒 GET；隐藏时停止轮询。
8. 退出登录或组件卸载时关闭 SSE、定时器和事件监听器。

已有 `credits:updated` 窗口事件继续兼容，用于当前页面在已知业务动作后立即刷新。

## 故障处理

- SSE 建立失败：不阻断页面，继续使用 GET 和轮询。
- SSE 中途断开：浏览器自动重连；重连成功后立即 GET。
- GET 暂时失败：保留最近一次成功余额，下一次事件、重连或轮询继续尝试。
- 后端重启：所有 SSE 连接断开；客户端重连和 GET 恢复。
- 事件重复：前端合并后重复 GET，余额不会重复扣减。
- 事件丢失：最多在下一次 60 秒轮询或页面恢复时校准。

## 安全与部署约束

- SSE GET 不修改业务状态，不引入跨站请求伪造写风险。
- 不把长期 JWT 放入 URL 查询参数。
- 生产环境继续要求 HTTPS 和 Secure、HttpOnly Cookie。
- Nginx 对 SSE 路径关闭响应缓冲，并将读取超时设置为大于服务端连接超时。
- 该方案只支持单个 backend 实例。若未来扩容为多个实例，必须增加跨实例广播，否则连接在其他实例上的设备可能漏通知。

## 测试策略

后端测试覆盖：

- 已登录用户可以建立 SSE，未登录用户得到 401。
- 同一用户的多个 emitter 都收到变化通知。
- 不同用户不会互相收到通知。
- emitter 完成、超时或出错后从连接表移除。
- 事务提交后发送通知，事务回滚不发送通知。
- 连接数超过限制时移除最旧连接。

前端测试覆盖：

- 登录后创建 EventSource，退出后关闭。
- 收到变化事件后触发账户 GET。
- 连续事件被合并，避免请求风暴。
- 页面恢复可见、网络恢复和 SSE 重新打开时刷新。
- 页面隐藏时停止轮询，恢复可见时重启。

## 验收标准

- 正常连接下，同一账号的两台设备在余额变化后 2 秒内显示新的 `available`。
- SSE 断开或事件丢失时，页面最迟在 60 秒轮询周期内恢复正确余额。
- 任意重复通知不会导致余额重复扣减或前端显示回退。
- 未登录用户无法订阅其他用户的余额事件。
- 后端和前端相关测试通过，用户端生产构建通过。

## 后续升级路径

当 backend 扩容为多个实例时，在不改变前端 SSE 协议的前提下增加 Credit Outbox 和 RabbitMQ fanout 广播。每个实例消费广播后，只向自己持有的 SSE 连接发送通知；账户 GET 仍保持权威读取职责。

# Agent 架构与维护指南

## 总体架构

```text
user-web -> Java backend (事实源 / SSE / 权限 / 积分 / 审计)
                 -> agent-service AgentRuntime
                    -> AgentGraphEngine / LangGraph StateGraph
                       -> ToolOrchestrator -> BackendToolBridge -> worker
```

Java backend owns users, sessions, messages, runs, tools, tasks, credits,
checkpoints, events, and audit. Python does not access the database or worker
directly.

## 唯一运行时

`AgentRuntime.execute_run`、`execute_confirmed_tool` 和 `debug_route` 都直接
调用 `AgentGraphEngine`。不存在旧引擎选择、JSON router fallback 或
DeepAgents 分支。`runtimeSettings.intelligenceLevel` 只影响本次运行的预算、
思考深度或工具策略，不决定引擎类型。

固定图节点：

```text
prepare_context -> model_decide -> route_action -> execute_builtin_action
  -> execute_product_tool -> reflect_or_retry -> wait_for_confirmation
  -> finalize_answer
```

`AgentState` 是唯一运行状态，包含消息、请求、上下文快照、计划、工具调用、
媒体产物、记忆、文件引用、待确认工具、迭代次数、错误和最终回答，并可完整
序列化到 backend checkpoint。

## 工具与安全边界

所有产品工具必须经过：

```text
LangGraph -> ToolOrchestrator -> BackendToolBridge -> Java internal API -> worker
```

Java 负责权限校验、积分冻结/结算、任务创建、状态更新和审计。高风险工具先
发出 `tool.confirmation_required`，保存 checkpoint，用户确认后恢复同一运行。

## 事件契约

前端只依赖稳定事件：

`run.started`、`agent.step`、`tool.selected`、`tool.requested`、
`tool.completed`、`tool.failed`、`tool.confirmation_required`、`plan.updated`、
`reflect.retry`、`message.delta`、`message.completed`、`run.completed`、
`run.failed`。

## 多模态、记忆与附件

`prepare_context` 冻结工作区记忆、文件上下文和可用工具；`SessionState` 注入
最近媒体与原始 prompt。`base_image_url` 与 `reference_images` 分离，附件指针
在工具执行前解析为真实 URL。记忆写入只能通过受控 memory tools 完成。

## 维护与验收

修改图节点时同步更新 `agent-service/app/runtime/agent_graph/`、Graph 测试、
事件类型和本指南。验证命令：

```bash
cd agent-service && pytest -q
cd ../backend && mvn test
cd ../user-web && npm run build
```

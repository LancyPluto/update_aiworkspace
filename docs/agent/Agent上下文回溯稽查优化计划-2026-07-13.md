# Agent 上下文回溯稽查优化计划

## 目标

管理后台必须能按一次 Run 还原输入事实、工具披露、Skill 水合、模型请求、参数校验和执行结果，
并用可复核证据区分上下文不全、工具不可见、披露遗漏、Skill 缺失、工具选错、参数错误和执行失败。

## 事实源

- `agent_context_snapshots` 保存 Backend 创建 Run 时的不可变输入快照，管理端不得重新计算历史上下文。
- `agent_model_request_snapshots` 保存 Agent Service 每次调用模型前的最终脱敏请求，包括消息、工具 Schema、
  Skill 版本、阶段、迭代、Token 估算和原始内容哈希。
- `agent_run_events`、`agent_tool_calls` 继续承担路由、披露、水合、参数和执行证据，不复制业务事实。
- `agent_run_audit_reviews` 保存管理员预期工具、人工分类和备注，不覆盖自动诊断与原始证据。

## 数据保护

- 审计正文写入前统一脱敏：密钥、Token、Cookie、Authorization、签名 URL 参数、手机号、邮箱和身份证号。
- data URL 只保留哈希标记；原始正文只计算 SHA-256，不保存未脱敏副本。
- 正文默认保留 30 天，到期后清空 payload，保留阶段、计数、哈希、诊断和时间元数据。
- 仅现有管理员可读；读取审计详情、模型请求和 Skill 覆盖均进入管理员操作审计。首版不提供批量全文导出。

## 排查链

后台固定按以下顺序展示证据：

1. 输入事实：用户消息、历史裁剪、附件、文件分块、引用、记忆和模型配置。
2. 可见工具：Run 获得的工具与被过滤原因。
3. 渐进披露：候选、shortlist、展开工具、Schema 哈希和节省量。
4. Skill 水合：匹配规则、版本、内容哈希、水合成功或失败原因。
5. 模型请求：每次最终消息、工具定义、Token 和相邻请求差异。
6. 参数与执行：模型参数、规范化参数、Schema 拒绝、任务分发和供应商结果。

自动诊断固定优先级为 `CONTEXT_INCOMPLETE`、`TOOL_NOT_VISIBLE`、`DISCLOSURE_MISS`、
`SKILL_MISSING`、`TOOL_SELECTION_MISMATCH`、`ARGUMENT_SCHEMA_ERROR`、`EXECUTION_FAILURE`、
`UNDETERMINED`。没有直接证据时不得推断为确定故障。

## 接口

- `GET /api/admin/v1/agent/runs/{runId}/audit`
- `GET /api/admin/v1/agent/runs/{runId}/model-requests`
- `PUT /api/admin/v1/agent/runs/{runId}/audit-review`
- `GET /api/admin/v1/agent/skills/coverage`
- `POST /api/internal/v1/agent/runs/{runId}/model-request-snapshots`

内部采集失败只记录告警，不阻断用户生成链路。正文保留天数使用系统设置
`agent.audit.payload_retention_days`，默认 30，范围 1 至 365 天。

## 验收

- 历史 Run 的上下文不受后续消息、附件、记忆、工具或 Skill 修改影响。
- 首次请求、工具展开、Skill 水合和参数重试均形成连续请求序号。
- 管理端能完成参考图缺失、错误视频选型、未发布 Skill、缺少必填参数和供应商失败五条排查路径。
- 审计正文过期后接口保留元数据并明确显示 `payloadExpired=true`。

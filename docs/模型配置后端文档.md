# AI 超市 — 后端开发说明

> **文档版本**：1.0  
> **更新日期**：2026-05-21  
> **读者**：后端开发人员  
> **状态**：前端（admin-frontend / user-web）已按本契约实现；**后端尚未实现**，当前前端默认走 Mock 数据。

---

## 1. 背景与目标

产品「AI 超市」需要一套**独立于旧工具任务体系**的配置与聊天能力：

| 端 | 页面 | 路由 | 职责 |
|----|------|------|------|
| B 端 | AI 工具管理 | `/tools` | 配置模型图标、能力、上架状态 |
| C 端 | AI 超市 | `/marketplace` | 展示已上架模型卡片 |
| C 端 | 模型聊天 | `/chat/{toolId}` | 统一聊天 UI，按能力动态渲染控件 |

**核心价值**：B 端配置 `capabilities` 后，C 端聊天页自动出现对应控件（图片比例、文件上传、联网开关等），无需改前端代码。

---

## 2. 与现有系统的关系（重要）

### 2.1 已有、继续保留的接口

旧体系**不要删除**，其他页面仍依赖：

| 模块 | 路径前缀 | 用途 |
|------|----------|------|
| 管理端工具 | `/api/admin/v1/tools` | 旧 AI 工具（任务型：toolType、fieldSchema、modelConfig） |
| 用户端工具 | `/api/v1/tools` | 工具超市（任务创建 `/api/v1/tasks`） |
| Agent 会话 | `/api/v1/agent/sessions` | Agent 编排聊天（与 AI 超市聊天**不是同一套**） |

### 2.2 本次新增（前端已对接，后端缺失）

| 模块 | 路径前缀 | 状态 |
|------|----------|------|
| B 端 AI 超市配置 | `/api/admin/ai-tools` | ❌ 未实现 |
| C 端 AI 超市 | `/api/v1/ai-tools`、`/api/v1/sessions`、`/api/v1/messages`、`/api/v1/chat/messages`、`/api/v1/upload` | ❌ 未实现 |

### 2.3 旧表 `ai_tools` vs 新模型

现有 `ai_tools` 表面向**任务型工具**（`tool_code`、`tool_type`、`estimated_credit_cost`、`model_config_id` 等），**不满足**新需求中的 `capabilities` JSON、字符串 `id`（如 `doubao`）、`welcomeMessage` 等字段。

**建议**：新建独立表 `ai_market_tools`（名称可调整），避免与旧逻辑耦合。若必须复用 `ai_tools`，需新增列并明确两套 API 的数据边界。

## 4. 数据模型

### 4.1 核心类型（与前端 TypeScript 一致）

```typescript
interface AITool {
  id: string                 // 业务唯一标识，如 "doubao"（非自增数字）
  name: string               // 显示名，≤20 字
  iconUrl: string            // 图标 URL
  description?: string     // ≤100 字
  enabled: boolean           // true= C 端可见
  order: number              // 排序，越小越靠前
  primaryColor?: string       // 主题色，如 "#3b82f6"
  welcomeMessage?: string    // 首次进入聊天页欢迎语
  capabilities: Capability[]
}

interface Capability {
  type: CapabilityType
  config: Record<string, any>
}

type CapabilityType =
  | "imageGeneration"
  | "fileReading"
  | "webSearch"
  | "codeExecution"
  | "voiceInput"
```

### 4.2 各能力 `config` 规范

| type | config 字段 | 说明 |
|------|-------------|------|
| `imageGeneration` | `aspectRatios: string[]` | 如 `["1:1","16:9","9:16"]` |
| | `defaultRatio: string` | 默认比例 |
| | `maxImagesPerRequest?: number` | 单次最大生成数，1–4 |
| `fileReading` | `supportedFileTypes: string[]` | 扩展名，如 `["pdf","txt","png"]` |
| | `maxSizeMB: number` | 单文件上限 MB |
| `webSearch` | `enabled: boolean` | 是否显示联网开关 |
| | `defaultEnabled?: boolean` | 默认是否开启 |
| `codeExecution` | `supportedLanguages: string[]` | 如 `["python","javascript"]` |
| `voiceInput` | `language?: string` | 如 `"zh-CN"` |

### 4.3 会话与消息

```typescript
interface Session {
  id: string
  title: string              // 默认「新对话」；首条用户消息后取前 20 字
  toolId: string
  createdAt: number          // Unix 毫秒
  updatedAt: number
}

interface Message {
  id: string
  role: "user" | "assistant"
  content: string
  timestamp: number
  attachments?: Attachment[]
  params?: Record<string, any>   // 如 { imageRatio: "16:9", webSearch: true }
}

interface Attachment {
  fileId: string
  name: string
  size: number
  type: string                 // MIME
}
```

## 5. 统一响应格式

与现有项目一致：

```json
{
  "code": "SUCCESS",
  "message": "ok",
  "data": { ... },
  "traceId": "optional"
}
```

失败时 `code` 使用现有 `ErrorCode` 枚举，建议复用：

| code | 场景 |
|------|------|
| `SUCCESS` | 成功 |
| `PARAM_ERROR` | 参数校验失败 |
| `UNAUTHORIZED` | 未登录 |
| `FORBIDDEN` / `ADMIN_FORBIDDEN` | 无权限 |
| `TOOL_NOT_FOUND` | toolId 不存在 |
| `TOOL_OFFLINE` | 工具已下架（C 端访问） |
| `MODEL_CALL_FAILED` | 调用大模型失败 |
| `SYSTEM_ERROR` | 系统异常 |

C 端聊天可新增（需同步 `user-web/src/api/types.ts`）：

| code | 场景 |
|------|------|
| `SESSION_NOT_FOUND` | 会话不存在 |
| `FILE_TYPE_NOT_ALLOWED` | 文件类型不允许 |
| `FILE_SIZE_EXCEEDED` | 文件超限 |

## 6. B 端接口（管理后台）

**鉴权**：Admin JWT，与 `/api/admin/v1/*` 相同。

### 6.1 获取全部 AI 工具

```
GET /api/admin/ai-tools
```

**响应 data**：`AITool[]`（含已下架，按 `order` 升序）

### 6.2 创建 AI 工具

```
POST /api/admin/ai-tools
Content-Type: application/json
```

**请求体**：

```json
{
  "id": "doubao",
  "name": "豆包",
  "iconUrl": "https://cdn.example.com/doubao.png",
  "description": "生图+文件阅读",
  "enabled": true,
  "order": 10,
  "primaryColor": "#f97316",
  "welcomeMessage": "你好，我是豆包~",
  "capabilities": [
    {
      "type": "imageGeneration",
      "config": {
        "aspectRatios": ["1:1", "16:9"],
        "defaultRatio": "1:1",
        "maxImagesPerRequest": 1
      }
    },
    {
      "type": "fileReading",
      "config": {
        "supportedFileTypes": ["pdf", "png"],
        "maxSizeMB": 20
      }
    }
  ]
}
```

**校验**：
- `id`：必填，唯一，建议 `[a-z0-9-]`，≤32
- `name`：必填，≤20 字
- `iconUrl`：必填
- `order`：正整数
- `description`：≤100 字
- `capabilities`：数组，每项 `type` 必须在枚举内

**响应 data**：完整 `AITool`

### 6.3 更新 AI 工具

```
PUT /api/admin/ai-tools/{id}
```

路径 `{id}` 为业务 id（如 `doubao`）。请求体同创建（`id` 可省略）。

### 6.4 删除 AI 工具

```
DELETE /api/admin/ai-tools/{id}
```

建议软删除。若该工具仍有活跃会话，可允许删除但 C 端不可新建会话。

### 6.5 上传图标

```
POST /api/admin/upload-icon
Content-Type: multipart/form-data
```

| 字段 | 说明 |
|------|------|
| file | 图片文件，支持 jpg/png/svg/webp，建议 1:1 |

**响应 data**：

```json
{ "url": "https://...或/generated/..." }
```

**可参考**：现有 `POST /api/admin/v1/tools/cover-upload` 的上传与存储逻辑。

## 7. C 端接口（用户端）

**鉴权建议**：
- 读工具列表/详情：可匿名（与当前前端 `requiresAuth: false` 一致）
- 会话、消息、聊天、上传：**建议登录**（`AuthContext.get().userId()`），与 Agent 会话一致

### 7.1 已上架工具列表

```
GET /api/v1/ai-tools
```

**响应 data**：`AITool[]`，仅 `enabled=true`，按 `order` 升序。

### 7.2 单个工具配置

```
GET /api/v1/ai-tools/{toolId}
```

- 存在且上架：返回 `AITool`
- 不存在：`TOOL_NOT_FOUND`
- 已下架：`TOOL_OFFLINE`（前端会跳转回超市）

### 7.3 会话列表

```
GET /api/v1/sessions?toolId={toolId}
```

**响应 data**：`Session[]`，当前用户 + 指定 toolId，按 `updatedAt` 降序。

### 7.4 创建会话

```
POST /api/v1/sessions
Content-Type: application/json

{ "toolId": "doubao" }
```

**响应 data**：

```json
{
  "id": "sess_abc123",
  "title": "新对话",
  "toolId": "doubao",
  "createdAt": 1710000000000,
  "updatedAt": 1710000000000
}
```

**业务**：`toolId` 对应工具必须存在且 `enabled=true`。

### 7.5 删除会话

```
DELETE /api/v1/sessions/{sessionId}
```

仅允许删除当前用户的会话；级联删除消息（或软删）。

### 7.6 会话消息列表

```
GET /api/v1/messages?sessionId={sessionId}
```

**响应 data**：`Message[]`，按 `timestamp` 升序。

### 7.7 发送消息并获取 AI 回复

```
POST /api/v1/chat/messages
Content-Type: application/json
```

**请求体**：

```json
{
  "toolId": "doubao",
  "sessionId": "sess_abc123",
  "content": "画一只猫",
  "attachments": ["file_456"],
  "params": {
    "imageRatio": "16:9",
    "webSearch": true,
    "language": "python"
  }
}
```

| 字段 | 说明 |
|------|------|
| `attachments` | 已通过 `/api/v1/upload` 获得的 `fileId` 列表 |
| `params.imageRatio` | 来自 `imageGeneration` 能力 |
| `params.webSearch` | 来自 `webSearch` 能力 |
| `params.language` | 来自 `codeExecution` 能力 |

**响应 data**（一次性返回，V1 不做 SSE；后续可扩展）：

```json
{
  "userMessage": {
    "id": "msg_u_1",
    "role": "user",
    "content": "画一只猫",
    "timestamp": 1710000001000,
    "params": { "imageRatio": "16:9" }
  },
  "assistantMessage": {
    "id": "msg_a_1",
    "role": "assistant",
    "content": "好的，这是一只猫……",
    "timestamp": 1710000002500
  }
}
```

**后端需实现**：
1. 校验 session 归属与 toolId 一致
2. 持久化 user / assistant 两条消息
3. 若会话 `title === "新对话"` 且为首条用户消息，更新 `title = content.substring(0, 20)`
4. 更新 session `updatedAt`
5. 根据 `toolId` 加载配置，调用对应大模型（可绑定 `model_config_id` 或独立配置表）
6. 将 `params`、`attachments` 传入模型/Worker

**可参考**：
- `AgentSessionController` + `AgentRunService` 的消息流转
- `TaskService` 的任务创建与 Worker 调度（若走异步生图）

### 7.8 上传文件

```
POST /api/v1/upload
Content-Type: multipart/form-data
```

| 字段 | 说明 |
|------|------|
| file | 用户选择的文件 |

**校验**（根据当前工具的 `fileReading` 能力）：
- 扩展名 ∈ `supportedFileTypes`
- 大小 ≤ `maxSizeMB`

**响应 data**：

```json
{
  "fileId": "file_789",
  "url": "/generated/..."
}
```

**可参考**：`AgentFileController` 的上传实现。

## 8. 业务规则清单

| # | 规则 |
|---|------|
| 1 | C 端列表/详情仅返回 `enabled=true` 的工具 |
| 2 | 下架后：C 端列表不展示；直接访问 `/chat/{toolId}` 返回 `TOOL_OFFLINE` |
| 3 | 下架后已有会话是否可继续发消息：**建议允许**完成当前对话，禁止新建会话 |
| 4 | 会话按 `user_id` 隔离 |
| 5 | 首条用户消息发送后，会话标题更新为首条内容前 20 字 |
| 6 | 发送消息后，前端会重置能力控件默认值（后端无需处理） |
| 7 | `id` / `sessionId` / `messageId` / `fileId` 建议使用带前缀的字符串，便于日志排查 |

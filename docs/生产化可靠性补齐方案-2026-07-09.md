# 生产化可靠性补齐方案（2026-07-09）

## 目标

本次补齐目标是把登录态、任务执行、失败成本、监控日志四条生产关键链路做成最小闭环：

- 浏览器端以 HttpOnly Cookie 作为主登录态，Bearer token 只保留兼容。
- Worker 执行任务前必须获得后端租约，避免 RabbitMQ 至少一次投递导致重复调用供应商。
- 失败任务默认不扣用户算力，但能记录供应商是否已计费、失败阶段和失败成本。
- Grafana 能看到业务指标、队列状态、失败成本，并能通过 traceId 查询跨服务日志。

本次不更换鉴权框架，不引入 OpenTelemetry，不引入 Flyway；沿用现有 JWT、DataInitializer、Micrometer、Prometheus/Grafana，并补齐 Loki 日志查询能力。

## 当前问题

- 后端已经下发 `ATM_USER_SESSION` / `ATM_ADMIN_SESSION` HttpOnly Cookie，但用户端和管理端仍会依赖 `localStorage` / `sessionStorage` token。
- RabbitMQ 和 Worker 已有 retry/DLQ，但任务执行前没有后端原子 claim/lease，重复消息可能重复调用非幂等供应商。
- 普通任务失败会释放冻结算力，但没有标准化记录失败阶段、供应商是否已计费和失败成本。
- 后端已有 `TaskMetrics` / `AgentMetrics`，但 Prometheus 尚未抓取 `/actuator/prometheus`；Grafana 还没有业务可靠性面板。
- 现有 `X-Request-Id` / `traceId` 能在部分链路透传，但缺少 Loki/Promtail 采集，无法在 Grafana 中按 traceId 查询跨服务日志。

## 实施措施

### 1. Cookie 主登录态

- 后端鉴权改为优先读取路径对应 Cookie：用户侧 `ATM_USER_SESSION`，管理侧 `ATM_ADMIN_SESSION`。
- Bearer token 仅作为兼容来源，保留给旧脚本、调试工具和特殊调用。
- 用户端和管理端默认只发送 `credentials: "include"`，不再自动从前端存储读取并拼接 Bearer。
- 用户端启动时通过 `/api/v1/users/me` 恢复登录，管理端通过 `/api/admin/v1/auth/me` 恢复登录。
- 启动和登出时清理旧 token 存储键，避免过期 Bearer 阻挡有效 Cookie。

### 2. 执行租约 / Claim Lock

- `ai_tasks` 增加 `claimed_by`、`claim_token`、`lease_until`、`claimed_at`、`lease_renewed_at`、`execution_attempt`。
- 新增内部接口：
  - `POST /api/internal/v1/tasks/{taskId}/claim`
  - `POST /api/internal/v1/tasks/{taskId}/lease/renew`
- Worker 收到任务消息后必须先 claim，claim 失败直接 ack 并跳过，不调用供应商。
- Worker claim 成功后才取 execution-context、调用供应商，并在 processing/success/failed 回调中带 `claimToken`。
- success/failed 回调只有 guarded SQL 真正更新成功后才允许进入结算、释放、写结果、写失败成本、工作流推进等副作用；guarded update 未命中且任务仍非终态时直接拒绝，避免旧 Worker 在租约过期后继续结算。
- success/failed/cancel/timeout 等终态必须保持幂等，不重复扣费、不重复释放、不重复写成本。

### 3. 失败成本归因

- 用户侧策略：失败/超时任务释放冻结额度，默认不扣用户算力。
- Worker 失败回调扩展字段：`failureStage`、`providerCharged`、`providerCostAmount`、`providerErrorCode`、`providerRequestId`、`promptTokens`、`completionTokens`、`billableUnits`、`claimToken`。
- `billing_usage_logs` 增加 `outcome`、`error_code`、`failure_stage`、`provider_error_code`、`provider_request_id`、`provider_charged`。
- 供应商已计费但任务失败时，写 `outcome=FAILED` 的 billing usage：用户扣费为 0，供应商成本正常记录。
- 手填厂商余额在 `providerCharged=true` 或 `providerCostAmount > 0` 且成本大于 0 时扣减，避免 Worker 漏传 `providerCharged` 时丢失真实供应商成本。

失败阶段枚举：

- `VALIDATION`
- `BEFORE_PROVIDER`
- `PROVIDER_SUBMITTED`
- `PROVIDER_POLLING`
- `MEDIA_PERSIST`
- `BACKEND_CALLBACK`
- `WORKER_INTERNAL`
- `UNKNOWN`

### 4. Grafana / TraceId / 日志

- Prometheus 增加 `backend-actuator`，抓取 `backend:8080/actuator/prometheus`。
- RabbitMQ 启用 Prometheus metrics 或 exporter，展示主队列、retry 队列、dead 队列、unacked 和 consumer。
- 增加 Loki + Promtail，采集 Docker stdout，Grafana 增加 Loki datasource。
- 后端、Worker、Agent 日志统一包含 `traceId`，Worker 回调后端继续透传 `X-Request-Id`。
- Grafana 新增中文业务面板：登录成功率、任务成功率、任务耗时、失败成本、队列积压、租约健康、Agent 工具调用、traceId 日志查询入口。
- Grafana 指标查询兼容 Micrometer/Prometheus 对 Counter 可能导出的 `_total` 命名差异。
- Promtail positions 使用持久化卷，避免监控容器重启后重复采集 Docker 日志。

## 本次落地范围

- 后端：Cookie 优先/Bearer 兼容、登出双 token revoke、任务 claim/renew 内部接口、guarded success/failed 回调、失败成本归因字段、登录/未授权/任务/租约/计费/Agent 指标。
- Worker：消费消息先 claim，claim 失败跳过；执行期间定时续租；processing/success/failed 自动带 `claimToken`；失败回调自动推断 `failureStage`。
- 用户端/管理端：默认 `credentials: "include"`，不再自动从 localStorage/sessionStorage 拼 Bearer；管理端 `AdminLayout` 直接以 `/api/admin/v1/auth/me` 恢复登录。
- 监控：Prometheus 抓后端 actuator 与 RabbitMQ；Loki/Promtail 采集 Docker stdout；Grafana 增加 Loki datasource 和中文可靠性 dashboard。

## 验收标准

- 刷新 `/admin/settings` 不再卡在“正在校验管理员登录状态...”。
- 浏览器默认请求没有 `Authorization: Bearer ...`，但 Cookie 登录有效。
- Cookie-only 用户和管理员 `/me` 能成功，登出后 Cookie 被清除且会话失效。
- 同一 RabbitMQ 消息重复投递时，只有一个 Worker 能 claim，供应商只被调用一次。
- 重复 success/failed/cancel/timeout 不重复扣费、不重复释放、不重复写成本。
- 失败/超时任务释放冻结额度；供应商已计费失败能在 billing 和 Grafana 看到，用户扣费为 0。
- Prometheus 能抓到后端 actuator 指标、RabbitMQ 队列指标、失败成本指标。
- Grafana Loki 能用同一个 `traceId` 查到至少 backend + worker 相关日志。
- 用户端、管理端、后端、Worker 的测试和构建全部通过。

## 回滚方式

- 登录态：后端继续兼容 Bearer；如 Cookie 主路径异常，可临时恢复前端显式 Bearer 发送。
- 执行租约：字段均为兼容新增；如 Worker claim 异常，可临时关闭 Worker claim 开关或回退 Worker 版本，后端字段不影响老任务读取。
- 失败成本归因：新增字段默认值不影响旧 billing 查询；如成本记录异常，可关闭失败成本写入，只保留失败释放。
- 监控日志：Prometheus/Grafana/Loki 均为旁路能力，异常时可单独回滚 monitoring compose，不影响核心业务。

## 非目标范围

- 不做 Flyway 迁移治理。
- 不做 OpenTelemetry/Tempo/Jaeger。
- 不做 MySQL 慢查询 exporter 和完整数据库备份体系。
- 不改变支付回调验签逻辑，不改变微信/支付宝支付入账边界。
